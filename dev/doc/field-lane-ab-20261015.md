## 安全（每趟都要确认，2026-10-15 事故后加严）

- 轮子架空，或场地空旷 + **有人持急停**；**跑动时人要在能立刻断电的距离内**（电池开关/插头）。
- **车不停时的处置顺序**：① **直接断电**（最可靠）；② **停止文件**（首选软件手段，见下）；
  ③ `bash /root/dev/scripts/stop_run.sh` / `pkill -TERM -f lane_final_test.py`；
  ④ Ctrl+C —— **只在「你前台手敲的这个窗口」里有效**（脚本启动日志会打印自检行：能到/到不了车）。
- 现场之所以会失控：**PCA9685 会一直输出最后一次写进去的脉宽** —— 主控进程一停（相机 UVC 卡死
  让 `cap.read()` 无限阻塞 / 进程被杀），车就带着最后的油门一直跑。
- **现在有了独立看门狗**（2026-10-15 加）：主控每帧喂心跳，**1.0s 不喂就把电调强行拉回 1500us**。
  · 跑动前确认日志里有这行：`[LANE] 电调看门狗已拉起（超时 1.0s …）`——**没有它就别跑**；
  · 看到 `[WATCHDOG] 🛑 心跳停了 … 强制安全值` = 主控刚卡死过、看门狗救了车：把这一趟日志发我。
  · 2026-10-17 起它**独立会话 + 忽略 Ctrl+C/断线信号**（操作员动手再也杀不掉这张安全网），
    自己的日志在会话目录 `esc_watchdog.log` 里。
- 跑完日志里必须有 `[BENCH] ✅ 已恢复**远程控制阶段**`，后面还跟着一行
  `⚠️ 注意：远程控制已恢复 = 网页摇杆/键盘现在能直接让车动` → **别把手机/网页停在摇杆页**。
- ★ **想停（2026-10-17 起，按这个顺序）**：
  1. **停止文件（首选，任何通道都能发）**：另开一个会话 / 串口 / 网页终端里
     `touch /dev/shm/lane_stop` —— 主循环**每帧**查它，走与 Ctrl+C 完全相同的安全收尾
     （电调归零、舵机回中、释放摄像头、恢复服务）。脚本启动时清残留、退出时也清；
     也等价于 `bash /root/dev/scripts/stop_run.sh --file`。
  2. `bash /root/dev/scripts/stop_run.sh`（车本地那个会话里敲；= 按 PID 发 TERM）。
  3. **Ctrl+C**：只有"你在这个窗口前台手敲、且它就是这个终端的前台作业"时才到得了车
     （启动日志有自检行；无 PTY/后台 `&`/nohup/在别的窗口按 → 都到不了）。10-16 那 7 趟就是
     按键没到（7 份日志零「收到信号」）。
  4. 把蓝板挡回下摄正前方**也能停，但不是闸门的功劳**：挡视线 → 丢线 → 维持 0.6s → 按丢线停
     （**还会往前滑一段**）。⚠️ 闸门发车后即闩锁，**没有「再见板即停」**（只有台架 `bench_test.py` 有）。
- ★★ **按了 Ctrl+C 之后，必须盯日志 3 秒**（2026-10-17 事故后的硬规矩）：
  · **必须看到** `[BENCH] 收尾（…）：` + `电调已归零、舵机回中、PCA9685 已释放` ⇒ 这趟才算停干净；
  · 一条 `[BENCH] 收尾` 都没有 / 看到 `退出码 134` / 看到 `⚠️⚠️ 电调归零失败 → **不解除看门狗**`
    ⇒ **立刻用停止文件**（另一个会话 `touch /dev/shm/lane_stop`）；**车还在动就直接断电**，
    车没动可以等 1 秒（那行日志的含义是"看门狗马上会强写 1500us"）。
  · 为什么要有这条：10-17 那次 `python3 … | tee` 的 **tee 先被 ^C 打死** → 我们的 stdout 变断管 →
    "电调归零"那一步被异常跳过、看门狗又被收掉 ⇒ 车一直跑，只能断电。现在修好了（`tee` 忽略 INT、
    打印绝不抛、断管自动接管到会话目录 `exit.log`、**电调没归零就不许解除看门狗**、收尾 `sync` 落盘），
    但"看一眼日志确认"是最便宜的最后一道保险。
  · 断电=重启会丢日志：rootfs `commit=600`（10 分钟才提交），所以**断电前能看一眼 `exit.log` / `session.json` 就看**。

## 第 2 步：三趟 A/B

**每趟重复这 5 个动作**：

1. 把车摆回起点（跟上一趟**同一个位置、车头同方向**）；
2. 敲这一趟的命令（见下）→ 出现提示后输入 `GO`；
3. 等屏幕出现 `[START_GATE] ✅ 已确认蓝板（…）→ 等待移开` → **把板移开** = 发车（车自己循迹，不用遥控）；
4. 车停下后（自己保护停 / 你 Ctrl+C / 到时 120s），跑一次汇总命令（第 3 步）；
5. 手机上记一行：目录名 + 这趟参数（如 `lane_run_161233 = kd0.24`）。

```bash
# 第 1 趟：基线（默认参数，kd=0.12 kp=0.15）
MAX_SECONDS=120 bash /root/dev/scripts/lab_lane_test.sh --run \
    --speed-us 1560 --save-every-s 0.2 --save-max 400

# 第 2 趟：阻尼加倍
MAX_SECONDS=120 bash /root/dev/scripts/lab_lane_test.sh --run \
    --speed-us 1560 --kd 0.24 --save-every-s 0.2 --save-max 400

# 第 3 趟：对齐上一届阻尼比（Kd/Kp=2.5）
MAX_SECONDS=120 bash /root/dev/scripts/lab_lane_test.sh --run \
    --speed-us 1560 --kp 0.10 --kd 0.25 --save-every-s 0.2 --save-max 400
```

三趟**都不要**先上 1580（今天四次 1580 全画龙发散；1560 稳）。想验速度就最后单独加一趟 `--speed-us 1580`。

## 常见现象对照

| 现象 | 含义 | 处置 |
|---|---|---|
| 启动后一直打印 `等待蓝板…`，车不动 | 板不够蓝/太小/不在视野 | 板拿近、对准下摄正前方；看打印的面积与主导度 |
| 发车后几秒自己停，日志里 `❌ 跑偏保护触发` | 误差持续 ≥60px（画龙/跑偏）——护栏在干活 | 记这趟为"发散档"，换下一档 |
| 日志里 `⚠️ 单侧持续 1.2s → 按丢线停车` | 只剩一侧超过 1.2s（出线或线出画）——新护栏 | 同上，这档没跟住 |
| `摄像头打不开 /dev/video2` | 别的进程占着（如 record.py 在录像） | 先停掉录像，再重跑（脚本会自己停/恢复副摄推流） |
| 跑完想复现 | 会话目录有 `run.csv` + `ann_*/raw_*.jpg`（0.2s 一张，640×384） | 拉下来给我 |
