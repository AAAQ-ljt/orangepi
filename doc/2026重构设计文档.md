# 2026 智能车重构项目 — 详细设计文档

> 版本:v0.1(评审稿)
> 适用比赛:第二十一届全国大学生智能汽车竞赛「室外 5G 远程驾驶无人车赛」(2026 规则未发布,按 2024+2025 规则推导)
> 硬件:香橙派 Orange Pi 5 V1.2(RK3588S,6 TOPS NPU,无板载 WiFi/蓝牙,M.2 M-Key=NVMe 专用),XT-NetRC 底盘
> 原则:全新代码库,不移植上一届业务代码;保留官方板卡 BSP、数据资产与知识资产

## 1. 项目目标与范围

### 1.1 目标
在香橙派 5(Orange Pi 5 V1.2)上构建一套**单板、全 Python、YOLO 感知、可回放调试**的智能车系统,覆盖:
1. 自主导航赛:发车→巡线→避障→斑马线停车播报→变道→引导锥桶区→AB 停车
2. 远程驾驶赛(预计回归):5G 图传 + 遥控驾驶 + 远程扫码付费
3. 开发期 AI 辅助:DeepSeek Harness 随车/本地运行,辅助编码、调参与技术手册撰写

### 1.2 明确的非目标
- 不在比赛实时链路中使用大模型(LLM 仅限开发期辅助)
- **不复制、不移植上一届任何业务代码**——上一届代码同样是 AI 生成、结构欠佳(1986 行单文件、全局 flags),复用价值低。允许并鼓励的是**借鉴其思路与经验参数**(状态划分、PID 范围、HSV 阈值、检测逻辑等作为行为基线),全部实现由 2026 团队重新编写
- 不追求 40km/h 极速;策略是**先稳后快**(评分公式为完赛队伍间的相对竞速)

### 1.3 复用的资产(非上一届业务代码)
| 资产 | 用途 |
|---|---|
| 官方镜像 BSP | `pca9685` 驱动参考、`hardware_Test`、ffmpeg 图传服务、frp 内网穿透、网页控制、键盘遥控参考实现 |

## 2. 约束与假设

| 项 | 内容 |
|---|---|
| 算力 | RK3588S:4×A76@2.4GHz + 4×A55@1.8GHz;NPU 6 TOPS;GPU Mali-G610(本项目不使用 GPU 推理) |
| 摄像头 | USB UVC 免驱摄像头(官方照片标注:上 USB=摄像头、下 USB=5G 模块),位置固定不可加高;CSI 作为备选接口预留 |
| 执行机构 | 全车舵机/电调/云台经 **PCA9685 十六路 PWM 板**驱动(实拍确认:PWM0-15 输出端子、V+/GND 电源端子、SDA/SCL 逻辑针),I2C5(SDA_M3/SCL_M3)连接;通道 0=转向舵机、1=电调、2/3=云台 |

| 网络 | **OPi 5 V1.2 无板载 WiFi/蓝牙,M.2 M-Key 槽是 NVMe SSD 专用(不能插 WiFi 卡)**;车载无线网卡来源到货后用 `lsusb`/`ip addr` 确认(大概率 USB 无线网卡,官方教程的热点连接依赖它),若缺则加购免驱 USB WiFi 网卡;5G 模块(SIM8202E-M2,M.2 HAT,ANT1-4 天线)用于远程驾驶图传;frp 域名访问 |
| 赛道 | 400m 田径场,约 200m 赛道,蓝底或红底(锥桶/标志配色随之变化) |
| 电源 | 12V 大电池→电调/电机(动力域);主控域/舵机域供电见下方「供电约束」——自带降压按树莓派 4B 设计,**供 OPi 5 大概率不足,计划外接电源**;24V 电池与 Jetson 分支整体拆除 |
| 系统 | 沿用官方镜像(Debian/Ubuntu + 预装服务),不重刷根文件系统 |

### 2.1 供电约束与外部电源方案(2026 重点)

**问题确认**:OPi 5 官方推荐 **5V/4A** Type-C 供电;满载(NPU 持续推理 + 摄像头 + WiFi/图传)功耗约 8~15W,瞬时峰值接近 20W。原车降压链路按树莓派 4B(峰值 ~7W)设计,典型模块仅 5V/2~3A,供给 OPi 5 会在 NPU 高负载时电压跌落→掉帧或瞬间重启。**结论:自带电源大概率不够,需外接电源或升级降压链路。**

**供电域划分(分轨,防互相拖垮)**:

| 供电域 | 负载 | 电源 | 规格要求 |
|---|---|---|---|
| 动力域 | 电调+电机 | 12V 大电池(自带) | 不动 |
| 主控域 | 香橙派 5 | **外接电源或加强降压** | 5V / ≥4A 连续,≤0.1V 纹波 |
| 舵机域 | PCA9685 V+、转向/云台舵机 | 独立 5~6V 降压 | ≥3A 连续、5A 峰值(舵机堵转 1.1~1.3A/个) |
| 通信域 | 5G 模块 | 官方长条降压 USB 输出(沿用) | 发射峰值 1~2A,**勿与主控共用一级降压** |

关键原则:主控域与舵机域**分轨供电**(舵机堵转大电流不拖垮香橙派);全车共地;各降压输出端并 1000µF 低 ESR + 100nF 电容防瞬态跌落。

**外接电源方案(二选一,到货实测定夺)**:
- **方案 A(推荐)**:外接 3S/4S 电池组(11.1V/14.8V)→ 两颗高质量 DC-DC:12V→5V/5A 供 OPi 5(Type-C 线短而粗)、12V→6V/4A 供舵机轨
- **方案 B(轻改)**:保留车内 12V 小电池,把原"充电宝降压模块"换成 ≥5A 带散热的真降压模块;舵机轨另加独立 6V 模块

**监测与保护**:
- 主控域串入 **INA219**(I2C)做电压/电流遥测,电压 <4.7V 报警并自动降载(关闭 NPU 推理、保控制与图传)——同时是技术手册的一个好案例
- 到货第一步用 USB-C 功率计实测板载满载电流,再确定降压模块规格,不盲目采购
- **合规确认**:2026 规则未出且今年有硬件检查;参考 2025 电气图虽有外加电池先例,外部电源方案仍须在官方 QQ 群书面确认,避免重蹈 Jetson 覆辙

**核心性能预算**(以 3 m/s 行驶速度计):
| 指标 | 目标 | 说明 |
|---|---|---|
| 端到端感知→控制延迟 | < 80 ms | 3 m/s 下对应 24 cm 行程;含采集、NPU 推理、控制输出 |
| 推理帧率 | ≥ 25 FPS | RKNN FP16 YOLO11n-seg 目标值 |
| 控制频率 | 30~50 Hz | 摄像头帧驱动 + 内部插值 |
| 启动到就绪 | < 30 s | 含模型加载、外设自检 |

## 3. 总体架构

### 3.1 进程模型:单板单进程
视觉与控制同板同进程(线程协作),**不沿用 Jetson+树莓派双机结构**。理由:无网络往返、延迟最低、部署最简单(一条命令启动)。模块间通过线程安全队列 + 数据类通信。

```
┌────────────────────────────── Orange Pi 5 ──────────────────────────────┐
│                                                                            │
│  ┌────────────┐   frame    ┌──────────────┐  PerceptionFrame  ┌─────────┐ │
│  │ Camera 线程 │ ─────────► │ 感知线程      │ ────────────────► │ 控制主循环│ │
│  │ (UVC 采集)  │  队列(丢旧) │ RKNN YOLO11  │    队列(丢旧)      │  FSM+控制器│ │
│  └────────────┘            │ 后处理/车道拟合│                    └────┬────┘ │
│                            └──────────────┘                         │      │
│  ┌────────────┐  telemetry  ┌──────────────┐   ControlCommand      │      │
│  │ 遥测/仪表盘 │ ◄────────── │ Recorder 线程 │ ◄────────────────────┘      │
│  │ (FastAPI)  │             │ (录制/日志)   │                            │      │
│  └────────────┘             └──────────────┘                            ▼      │
│  ┌────────────┐        ┌────────────────────────────────────────────────────┐ │
│  │ Teleop 服务 │ ─────► │                硬件抽象层 HAL                     │ │
│  │ (TCP/WS)   │ 安全仲裁 │  PCA9685(舵机/电调/云台) IMU GPS 音频 摄像头        │ │
│  └────────────┘        └────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────────┘
```

- **丢旧策略**:所有队列 `maxsize=1`(取最新帧),天然抗延迟累积
- **遥测**:结构化 JSONL 日志 + WebSocket 仪表盘(实时看 FSM 状态、帧率、延迟、参数)
- **录制**:所有输入输出旁路录制,支撑离线回放调试

### 3.2 数据流核心契约:PerceptionFrame
感知模块的唯一输出,控制模块的唯一输入(与控制频率解耦):

```python
@dataclass
class PerceptionFrame:
    timestamp: float                 # 采集时刻(单调时钟)
    frame_id: int                    # 递增帧号
    # 车道(分割掩膜后处理产物)
    left_lane: LanePoly | None       # 左车道线多项式(图像坐标系)
    right_lane: LanePoly | None
    # 检测目标
    cones: list[ConeDetection]       # 蓝/黄锥桶:bbox、类别、中心点、距离估计
    barrier: BarrierInfo | None      # 蓝色挡板:存在性 + 覆盖面积占比
    zebra: ZebraInfo | None          # 斑马线:存在性 + 纵向位置(近/中/远)
    lane_change_sign: Literal["left","right"] | None
    parking_sign: Literal["A","B"] | None
    # 元数据
    inference_ms: float              # NPU 推理耗时
    confidence: dict[str, float]     # 各类别置信度摘要
```

控制输出契约:

```python
@dataclass
class ControlCommand:
    steer_norm: float        # -1.0(左满) ~ +1.0(右满),映射到舵机脉宽
    throttle_norm: float     # -1.0(倒车) ~ +1.0(满油门),映射到电调脉宽
    gimbal: tuple[float,float] | None  # 云台(水平,垂直)
    broadcast: str | None    # 语音播报文本
    source: str              # 来源:autonomy / teleop / safety
```

## 4. 模块详细设计

### 4.1 `hardware/` — 硬件抽象层(接口 + 双实现)
所有硬件访问收敛到协议接口,**提供 `Mock` 实现**用于无车开发和 CI:

```python
class PWMController(Protocol):        # PCA9685 封装
    def set_pulse(self, channel: int, us: float) -> None: ...
class SteeringServo(Protocol):
    def set_normalized(self, value: float) -> None: ...   # -1..1, 内置标定/限幅
class ThrottleESC(Protocol):
    def set_normalized(self, value: float) -> None: ...
    def arm(self) -> None: ...        # 上电自检:中位→最低,含解锁蜂鸣流程
class Gimbal(Protocol): ...
class IMUSensor(Protocol): ...
class GPSSensor(Protocol): ...
class AudioPlayer(Protocol): ...
class CameraSource(Protocol):         # 采集线程封装,输出 numpy 帧
    def read_latest(self) -> Frame | None: ...
```

实现要点:
- **PCA9685 自研驱动**(约 100 行,基于 `smbus2` 或 `python-periphery`):50Hz 刷新、prescale 计算、OE 引脚、上电复位时序;I2C 总线号/地址写入 YAML(`i2cdetect` 实测确认,官方标注为 I2C5)
- **舵机标定**:脉宽 500~2500µs ↔ ±90°,逐车标定表中点/限幅(比赛规则给的是 45g 舵机规格)
- **电调安全**:上电默认 0 油门;解锁需显式调用;任何异常退出走 `SafetyStop`(见 6.2)
- **语音播报**:官方音箱,预录 MP3 + espeak 兜底;播报文本由控制层指定(学校+队名,规则固定句式)
- **传感器使用策略**:IMU(三轴角度,偏航角精度 0.5°)优先——用于变道/停车入位的姿态与航向粗判;GPS(2.5m/1Hz)仅做速度/里程遥测与"里程超限兜底报警",**不进入控制主链路**

### 4.2 `perception/` — 感知流水线
```
Frame → 预处理(可选:ROI/CLAHE,先全部关掉做基线) → RKNN 推理 → 后处理
     → 分割掩膜→车道多项式拟合     → LanePoly
     → 检测框 →锥桶/标志/斑马线/挡板 → Detections
     → 组装 PerceptionFrame
```
- **模型策略**:YOLO11-seg 迁移学习(12 类,见 §7);nano 为主、small 备选;FP16 优先,精度不足再 int8(需校准集)
- **车道拟合**:掩膜 → 骨架化(OpenCV 形态学)→ 底部起采样点 → 二次/三次多项式拟合(参考去年 `lane_follower` 思路,重写为可测试的纯函数)
- **时序滤波**:检测结果过 `ErrorFilter`(连续 N 帧确认才生效,单帧闪烁丢弃),参数进 YAML
- **距离估计**:锥桶/标志用「底部 bbox 纵向位置 + 摄像头俯角标定」粗估,不追求精确,只分近/中/远档位

### 4.3 `control/` — 表驱动状态机 + 控制器

**FSM 状态**(与 2025 任务链一一对应):
```
BOOT → WAIT_START(蓝挡板在) → TRACKING(巡线)
     → AVOID(弯道锥桶) → TRACKING
     → ZEBRA_STOP(停 10s+播报) → TRACKING
     → LANE_CHANGE(左/右) → GUIDE_CONES(引导锥桶区) → TRACKING
     → PARKING(A/B) → DONE
```

**表驱动**:`config/fsm.yaml` 描述转移,运行时是纯解释器,不写 if-else 链:
```yaml
state: TRACKING
transitions:
  - event: [zebra_near]          → ZEBRA_STOP
  - event: [cone_near]           → AVOID
  - event: [sign_left, sign_right] → LANE_CHANGE (参数=方向)
  - event: [park_sign_A, park_sign_B] → PARKING
  - event: [barrier_removed]     → (忽略,已处理)
  - timeout: 25s 无进度          → FAILSAFE_STOP
```
每个状态实现 `on_enter / on_frame(pf) / on_exit` 三个钩子;事件由「感知结果 + 计时器 + 行驶距离(轮速/IMU 积分)」共同生成。

**控制器(统一横向律)**:所有状态只输出「期望横向目标」,由一个 PID(可替换为纯跟踪)换算舵机:
- TRACKING:目标 = 车道中线加权误差(权重矩阵进 YAML,近端权重高)
- AVOID / LANE_CHANGE / GUIDE_CONES:目标 = 横向偏移(按锥桶/标志位置计算的偏移量),平滑过渡(斜坡限速)
- PARKING:目标 = 停车区中心,接近后减速→四轮入区→停车
- 纵向:基础速度档位 + 状态降速曲线 + 斑马线/停车前刹车斜坡;全部参数 YAML

### 4.4 `teleop/` — 远程驾驶(2026 预计回归)
- **控制通道**:TCP 服务(自定义 JSON 协议)+ 可选手柄支持;PC 端发送端(键盘监听 + 手柄)独立小工具
- **与自主模式互斥**:`source` 仲裁,遥控优先、看门狗兜底(500ms 无指令 → 减速停车)
- **图传**:直接复用官方镜像 `ffmpeg-stream.service` + frp(域名访问),本模块只做「低延迟调优」(分辨率/码率/关键帧间隔参数化)
- **可复用资产(实拍确认)**:官方网页控制已实现 WS 视频流、解锁/上锁/急停、油门/转向、云台摇杆、**手柄控制开关**、按住说话(UI 含 `armed/estop/throttle/steering` 状态)——远程驾驶 v1 直接复用官方网页控制,自研 TCP 遥操作作为 v2 进阶
- **远程扫码付费**:图传画面内操作,不需要额外开发;技术手册中记录流程即可

### 4.5 `recorder/` + `replay/` — 回放闭环(本项目最大工作流升级)
- **录制**:帧(JPEG)+ PerceptionFrame JSON + ControlCommand JSON + 传感器,按时间戳写入环形目录;行车全程录制,无性能影响(独立线程)
- **回放**:CLI 以录播数据驱动**同一套** perception/control 代码,支持单步、倍速、断点、参数热改;`tests/` 用固定录播集做回归
- **产出**:每次调参先在 PC 回放验证,再上赛道;比赛前积累「场景库」(锥桶、斑马线、变道、停车)

### 4.6 `telemetry/` — 仪表盘
- FastAPI + WebSocket:摄像头 JPEG 流、FSM 状态机图、帧率/延迟曲线、参数实时编辑(热生效)
- 结构化 JSONL 日志:每帧一行(状态、误差、控制量、置信度),赛后/回放后可直接分析

### 4.7 `config/` — 配置驱动
所有可调参数集中 YAML(`pydantic` 校验,启动时 fail-fast):
```yaml
hardware: {i2c_bus: 5, pca9685_addr: 0x40, servo: {...校准表}, esc: {...}}
perception: {model: rknn 路径, conf: {...各类别阈值}, filter: {连续帧N}}
control: {pid: {kp,ki,kd}, speed: {...档位}, fsm: 见上}
teleop: {watchdog_ms: 500, max_speed: 0.6}
camera: {width, height, fps}
```

## 6. 安全设计(比赛一次定胜负,崩溃即失败)

1. **全局 SafetyStop**:任何线程异常 → 油门归零 + 舵机回中,信号处理(SIGINT/SIGTERM)同样路径
2. **看门狗**:控制循环心跳;感知线程 500ms 无输出 → 减速停车;遥测可远程触发急停
3. **软限位**:舵机/油门输出一律限幅,标定值越界拒绝启动
4. **电调上电安全**:启动流程强制「中位→解锁」时序,防止车窜出
5. **降级模式**:RKNN 加载失败/推理异常 → 自动切入 B 方案(见 §9)

## 7. 数据集与训练策略(迁移学习)

- **类别**(沿用去年 12 类,保证权重可直接加载):`left_lane/right_lane/L0/L1/R0/R1`、`lane_change_sign_left/right`、`parking_sign_A/B`、`obstacle_cone_blue/yellow`、`zebra_crossing`
- **流程**:去年权重初始化 → 新车摄像头实拍采集(`tools/` 采集器)→ 旧模型**伪标注 + 人工修正**(半监督,标注量减半)→ 数据增强(亮度/阴影/模糊/透视,赛道光照是最大变量)→ 微调
- **转换链**:`.pt → ONNX → RKNN`(rknn-toolkit2 在 x86 PC 上完成);量化 FP16 优先,int8 需校准集;PC 模拟器先验证精度再上板
- **验收**:每类 mAP + 真实场景帧率/延迟基准;未达 FP16 目标再评估 int8
