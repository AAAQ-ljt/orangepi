## 0. 一页速览

```text
【模型】      3 类：traffic_light_off / traffic_light_red / traffic_light_green
【数据】      录视频（不是拍单张）→ 按事件抽帧（不是均匀抽帧）
【摄像头】    云台摄像头，按距离分 3 档俯仰角
【决策】      连续 5 帧绿灯 + 置信度阈值；禁止单帧决策
【兜底】      传感器不触发 → 超时保守停车
【二次校验】  模型 + 框内 HSV 颜色占比，两者不一致判 unknown
【规则红利】  红绿灯停车时长会从 T有效 里扣掉 → 等待几乎免费；
              抢灯 +20s 且不扣等待时长，未停 +50s → 策略必须"宁可多等"
```

## 1. 规则与场地复现

**规则要点**
- 赛事方在**距红绿灯 1m** 处的跑道**右（或左）侧**放置**光敏传感器**；
- 小车**经过传感器 → 触发 → 红绿灯亮红灯** → 小车**停车等待** → 绿灯亮 → 通过；
- 红灯时长**随机 3~10s**；
- 红绿灯**横置**在离地 **40cm** 的架子上，**装在赛道正上方居中**（规则 §2.2.5）。

**形态（2026-09-15 按规则初稿图 7 确认）**：**横排三灯珠**，红-黄-绿从左到右，灯箱 60×17×6.7cm。**"灭灯" = 三珠全灭**。
→ 标注仍框整个灯箱；但 **HSV 二次校验应按左 1/3（红）、右 1/3（绿）分区统计**，比整框占比稳。
（规则初稿图 10 把灯画成竖排，属示意图不一致，以图 7 实物照为准。）

**关键推论**：小车必须**先经过传感器（触发）**，灯才会变红。所以停车点是"传感器之后、红绿灯之前"（即"传感器与红绿灯所围区域"），**不是"看到红绿灯就停"**；且停车时**车头前轮不得超出该区域**。

## 2. 硬件准备

### 2.1 光敏传感器（必须更换）

| 项 | 现状 | 要求 |
|---|---|---|
| 触发距离 | 现购（官方淘宝店）仅 **20cm** | **≥1m** |
| 阈值 | 固定 | **现场可调**（比赛场地光照不可控） |

**推荐型号**
- **E18-D80NK 红外光电开关**：3~80cm 可调、数字量输出、抗环境光 ✅ 首选
- 备用：光敏电阻 + **LM393 可调比较器** + **遮光筒**（减少环境光干扰）

**接线**：数字输出 → 香橙派 GPIO → 中断或轮询（建议**中断 + 软件去抖**）

### 2.2 云台摄像头

- 先用 `ls /dev/video*` + `v4l2-ctl --list-devices` 枚举；
- **逐个抓帧存图肉眼确认**哪一路是云台摄（不要靠猜）；
- 记录到 `config/` 供代码读取。

### 2.3 灯控装置（仅采集用）

采集时需要能程序控制灯色循环。可用：
- 自制灯箱 + 单片机/继电器控制；
- 或直接用赛事同款红绿灯 + 手动开关（人工按秒表切换）。

## 3. 数据采集方案

### 3.1 核心原则

> **录视频，不要拍单张。**
> 因为需要的不只是"红灯长什么样"，而是「**灭 → 红 → 绿**」的完整过程，
> 尤其是 **红→绿的过渡瞬间** —— 那才是真正的决策点。

### 3.2 灯控时序（采集用）

```text
灭 5s → 红 5s → 绿 5s → 灭 5s → 循环     （每循环 20s）
```

### 3.3 拍摄矩阵

| 维度 | 取值 | 说明 |
|---|---|---|
| **距离** | 5m / 3m / 2m / 1m | 覆盖"刚能看见"到"停车位置" |
| **横向偏移** | 灯在画面 左 / 中 / 右 | 车不一定正对灯 |
| **光照** | 正午强光 / 黄昏 / 阴影 / 逆光 | **强光下灯珠对比度极低，是最大坑** |
| **车状态** | 行驶接近 + 静止等待 | 行驶有运动模糊，静止是真实决策场景 |

**估算**：4 距离 × 4 光照 × 3 横向 ≈ **48 段**，每段 60s ≈ **48 分钟素材**

### 3.4 怎么拍（关键）

**方案一（主力，推荐）：用小车自己的云台摄像头录**
- 把车放在轨道上，**遥控行驶**按"由远及近"的路线走完整过程；
- 云台按标定角度；
- 好处：**输入分布 = 部署分布**（分辨率、畸变、曝光、白平衡全部一致），模型不会"水土不服"。

**方案二（补充）：手机录**
- 方便快速补数据；
- 但分辨率/畸变/曝光/白平衡与车载摄像头不同 → **只作补充，不作主力**。

> ⚠️ **一定要录"从远处接近 → 停下等待 → 起步通过"的完整过程**，不要站着不动拍。

### 3.5 抽帧规则（不要均匀抽！）

| 阶段 | 抽帧密度 |
|---|---|
| 灭灯稳定期 | 每 0.5s 抽 1 帧 |
| **灯色切换瞬间**（灭→红、红→绿） | **前后各 1s 内每 0.1s 抽 1 帧** |
| 红灯稳定期 | 每 0.3s 抽 1 帧 |
| 绿灯稳定期 | 每 0.3s 抽 1 帧 |

**过渡帧必须单独归档**（`transition_frames/`），**不得丢弃** —— 这是决策点，也是最容易出错的地方。

### 3.6 目标数量

| 类别 | 目标实例数 |
|---|---|
| `traffic_light_off` | **≥ 400** |
| `traffic_light_red` | **≥ 400** |
| `traffic_light_green` | **≥ 400** |

比一般类别（200）要求更高，原因：
1. 红绿灯是 **2026 新增元素**，没有任何历史数据；
2. 它是**"停 / 走"的生死决策点**，误判代价极高；
3. 需要覆盖 4 种光照 × 4 种距离。

**配比提醒**：
- 三类大致 **1 : 1 : 1**；
- 但**更关键的是"近距离的 green 必须够多"** —— 因为真正用来决策的是停车等待时看到的绿灯。

## 4. 标注规范

### 4.1 类别（3 类）

```yaml
0: traffic_light_off     # 灭灯（必须标！否则会把灭灯误判成绿灯 → 抢跑）
1: traffic_light_red     # 红灯
2: traffic_light_green   # 绿灯
```

### 4.2 框什么

**框整个灯箱**，不是只框"亮着的那颗灯珠"。

理由：
- 灯箱是固定物体，位置稳定；灭灯时也要能框得住；
- 模型只需判断"这个框当前处于什么状态"；
- 若是横向三灯珠排列，框整个灯箱能让模型学到"红在左 / 绿在右"的空间线索。

### 4.3 标注一致性

- 同一个灯箱在**所有帧里框的边界要一致**（统一用灯箱外沿，不要一会儿框灯珠、一会儿框支架）；
- **严重模糊 / 完全遮挡的帧不要标**，但单独存到 `hard_cases/` 供复盘；
- Roboflow 导出选 **YOLO TXT (Detection)**。

## 5. 数据校验清单（训练前必做）

- [ ] 每类实例数 ≥ 400
- [ ] 4 种光照均有覆盖（尤其是**正午强光**）
- [ ] 4 种距离均有覆盖（尤其是 **1m 近距离**）
- [ ] 过渡帧已单独归档且**未丢弃**
- [ ] **同一视频片段不跨 train/val**（按片段整组切分，见 `split_dataset.py`）
- [ ] 检查是否存在"某个距离档下 green 一张都没有"
- [ ] 人工抽查 30 张，确认 off/red/green 无错标
- [ ] 确认 off / red / green 三类数量没有数量级差异

## 6. 比赛时方案

### 6.1 时序

```text
[进入 TRAFFIC_LIGHT 前]
   斑马线停车完成 → 云台抬头（预设角度）→ 视觉切云台摄 → 减速

[TRAFFIC_LIGHT]
   轮询光敏 GPIO
     ├ 收到触发 → 确认红灯 → 停车等待
     └ 未收到   → 低速继续前进（灯不会变红）

[停车等待中]
   5 FPS 检测灯色
     ├ off / red / unknown → 继续等
     └ 连续 5 帧 green 且置信度达标 → 起步

[起步]
   加速通过 → 云台复位 → 视觉切回下摄
```

### 6.2 状态机接口

| 输入 | 来源 | 说明 |
|---|---|---|
| `photocell_triggered` | GPIO | 边沿触发 + 软件去抖 |
| `light_state` | 云台摄 + 模型 | off / red / green / unknown |
| `light_conf` | 模型置信度 | |
| `t_elapsed` | 计时器 | 超时用 |

| 输出 | 说明 |
|---|---|
| `tl_phase` | `WAIT_TRIGGER` / `WAIT_GREEN` / `PASSING` |
| `stop_cmd` | 停车指令 |

### 6.3 时序滤波（关键，禁止单帧决策）

```text
等待绿灯判定：
    连续 5 帧 都是 green 且 conf > 0.7  → 才允许起步

红灯判定：
    连续 3 帧 red 即可认定（保守策略，宁可多等）

不确定：
    off / unknown / 模型与 HSV 不一致 → 维持停车
```

> ⚠️ 红→绿过渡帧若被误判为绿灯，会直接导致**抢跑**（规则上是严重违规）。

### 6.4 光敏传感器异常处理（需按规则确认）

| 策略 | 行为 | 风险 |
|---|---|---|
| **A. 保守（推荐）** | 到预期位置仍未触发 → 停在红绿灯前等待，超时 T=60s 后低速通过 | 若灯本就不会红，白白浪费几十秒 |
| **B. 激进** | 未触发 → 判定传感器失效 → 直接通过 | 若只是晚触发，灯变红时车已进入 → **违规** |

> **推荐策略 A**：竞速的损失是几十秒，违规的损失可能是**取消成绩**。

### 6.5 云台分档标定

| 距离 | 云台俯仰档位 |
|---|---|
| ≥ 4m | 档位 1 |
| 2 ~ 4m | 档位 2 |
| < 2m | 档位 3 |

- 用**实际车 + 实际灯**现场标定，参数存 `config/`；
- **不要用连续视觉伺服**（复杂且抖动），用固定档位切换。

## 7. 二次校验（HSV）

在模型检测框内做 HSV 分析：

```python
r_ratio = 红色像素占比
g_ratio = 绿色像素占比

if r_ratio > 0.15 and r_ratio > 2 * g_ratio:  → red
if g_ratio > 0.15 and g_ratio > 2 * r_ratio:  → green
else:                                          → unknown
```

- 模型与 HSV **一致** → 采用；
- **不一致 → 判 unknown**（不冒险）；
- 强光下灯珠对比度低时 HSV 可能比模型更可靠，两者互补。

## 8. 风险与兜底

| 风险 | 应对 |
|---|---|
| 强光下灯珠看不清 | 数据覆盖正午强光；HSV 二次校验；必要时给摄像头加遮光罩 |
| 灯箱被遮挡 | 云台多角度扫视；车辆静止时可多帧累积 |
| 传感器不触发 | 超时兜底（策略 A） |
| 传感器误触发（影子/反光） | 硬件去抖 + 连续 N 次确认 |
| 过渡帧误判成绿灯 → 抢跑 | 连续 5 帧 + 置信度阈值 + 过渡帧专项训练数据 |
| 云台角度不对 | 分档标定 + 多帧尝试 |
| 灯全灭 / 故障 | 视为 unknown → 维持停车 → 超时走策略 A |
