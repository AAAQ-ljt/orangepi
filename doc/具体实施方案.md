## 3. 2026 任务链（按规则初稿，覆盖设计文档 §4.3 更新）

```
遥控阶段(5G)  1 起点 ──遥控──▶ 2 切换区（停入、启动自动驾驶）
自主阶段      挡板移除(蓝挡板=发车信号)
             → TRACKING 沿跑道线巡线
             → ZEBRA_STOP 斑马线 停10s + 播报"我是***（学校）***(队名)的智能车，请为我加油！"
             → TRAFFIC_LIGHT 红绿灯:光电触发 3~10s 随机倒计时,红灯停、绿灯通行 ★2026新
             → AVOID 两处锥桶(蓝/红锥随机位置,靠左/中/右) ★随机
             → PARKING 上下两个停车区,裁判随机放挡板 → 停未被挡的区(四轮入区)
             → 30s 内远程扫码付 0.01 元(+5 分)
```

> **对感知/控制的影响（重要）**：
> - 红绿灯倒计时**随机 3~10s** → 必须**识别红灯/绿灯状态**（smartcar.yaml 已有 traffic_light_red/green），不能死计时
> - 锥桶位置随机 → 近端避障必须有实时性（感知→控制 <80ms 目标）
> - 停车区上下随机 → 识别蓝色挡板位置，选未遮挡区 → FSM 增加 TRAFFIC_LIGHT 状态，删除 2025 的变道/引导区状态（规则无此元素）
> - 人行道停车 10s + 播报（2026 初稿，非 5s）

## 4. 骨架代码落地（A 机 DSH，按设计文档 §5 目录）

```
2026-orange-pi/          ← 建议以独立包置于车 /root/2026-orange-pi（不动官方任何东西）
├── main.py              # 装配/自检/信号处理(优雅退出→SafetyStop)
├── config/              # YAML + pydantic(3.8 兼容)
├── perception/          # camera / rknn / postprocess / lane_fit / filter
├── control/             # fsm(表驱动解释器+状态) / pid / speed_planner
├── hardware/            # pca9685/servo/esc/gimbal/imu/gps/audio/camera + mocks/
├── teleop/              # ws 客户端对接官方 9001 或自研 TCP(待图传决策)
├── recorder/ replay/    # 录制/回放闭环(每轮联调必录)
├── telemetry/           # FastAPI 仪表盘 + JSONL 日志
├── tools/               # 采集/伪标注/rknn 转换
└── tests/               # pytest + 录播回归
```

**里程碑 M1（骨架，3 天）**：目录 + HAL 接口(Protocol)+ Mock + PerceptionFrame/ControlCommand + FSM 解释器跑通 BOOT→DONE（假数据演练）→ 全量单测过
**里程碑 M2（硬件点亮，2 天）**：PCA9685 驱动 + 舵机/电调标定 + 摄像头取流 + 安全自检（电调解锁时序、SafetyStop 信号路径）
**里程碑 M3（感知上板，取决于数据）**：RKNN 模型 + FPS/延迟基准 ≥25FPS / <80ms
**里程碑 M4（控制联调）**：FSM 全状态真车跑，录播复盘调参
**里程碑 M5（手动驾驶）**：图传 + 摇杆 + 5G 遥控跑通（先官方通道）
**里程碑 M6（模拟赛+手册）**：全流程 3 次模拟跑 + 5 案例技术手册

## 9. 风险备忘

| 风险 | 应对 |
|---|---|
| 红绿灯倒计时随机（3~10s）识别不稳 | 数据重点采倒计时场景；FSM 红/绿双态 + 连续帧滤波 |
| 锥桶随机位置撞桶(+20s/拖桶2m=失败) | 近端避障优先保"不撞"，宁可慢 |
| 手机热点不稳（遥控阶段裁判可能查"局域网"） | 比赛用手车 4G/5G 模块，非热点；日常开发热点可接受 |
| frp 隧道延迟波动 | pool_count 预连接 + 图传决策后评估自建 |
| 外部电源合规 | 官方 QQ 群书面确认后再动供电（设计文档 §2.1） |
