# 5G图传配置实验

> 本文档根据《5g图传配置.mp4》提取的视频帧整理，配合 `frames/` 目录下的截图查看。
> 适用对象：OrangePi 5 小车，当前本车编号为 `car027`。
> 核心目标：把官方默认的 `car0003` 图传/网页通道改成自己小车的编号，并完成服务重启与验证。

---

## 一、实验目的

1. 理解 5G 图传链路：小车摄像头 → FFmpeg 推流 → 官方媒体服务器 → 浏览器。
2. 掌握图传相关配置文件的修改位置。
3. 学会把默认编号 `car0003` 修改为本车编号 `car027`。
4. 掌握修改后重启 `ffmpeg-stream`、`ffmpeg-stream-sub`、`frpc` 服务的方法。
5. 能通过浏览器验证图传画面和控制通道是否正常。

---

## 二、配置前准备

- 已通过 SSH 连接小车：
  - 公网隧道：`ssh -p 2222 root@121.40.149.155`
  - 或热点直连：`ssh root@10.68.1.43`
- 小车已联网（5G SIM 或 WiFi 热点）。
- 已确认本车编号，例如 `car027`。

---

## 三、需要修改的文件

| 文件 | 位置 | 作用 |
|---|---|---|
| `frpc.ini` | `~/frp/frpc.ini` | frp 客户端配置，控制网页/图传隧道 |
| `talk_player_loop_sh` | `~/talk_player_loop_sh` | 语音/对讲相关循环脚本，包含车编号 |
| `ffmpeg-stream.service` | `/etc/systemd/system/ffmpeg-stream.service` | 主图传推流服务 |
| `ffmpeg-stream-sub.service` | `/etc/systemd/system/ffmpeg-stream-sub.service` | 副图传/备用推流服务 |

---

## 四、配置步骤

### 1. 修改 frpc.ini

```bash
cd ~/frp
nano frpc.ini
```

把文件中的：

```text
car0003
```

全部改成：

```text
car027
```

保存退出。

---

### 2. 修改 talk_player_loop_sh

```bash
cd ~
nano talk_player_loop_sh
```

同样把 `car0003` 改为 `car027`，保存退出。

---

### 3. 修改 ffmpeg 推流服务

```bash
cd /etc/systemd/system
nano ffmpeg-stream.service
nano ffmpeg-stream-sub.service
```

分别把两个文件中的 `car0003` 改为 `car027`，保存退出。

> 注意：这两个文件属于 systemd 服务配置，修改前建议先备份：
> ```bash
> cp ffmpeg-stream.service ffmpeg-stream.service.bak
> cp ffmpeg-stream-sub.service ffmpeg-stream-sub.service.bak
> ```

---

### 4. 重启服务

```bash
sudo systemctl daemon-reload
sudo systemctl restart ffmpeg-stream.service
sudo systemctl restart ffmpeg-stream-sub.service
sudo systemctl restart frpc.service
```

---

### 5. 验证图传

- 打开浏览器访问：
  ```text
  http://121.40.149.155:8080
  ```
  或官方子域名页面。
- 应能看到小车摄像头实时画面。
- 网页上的控制通道应显示已连接/在线。
- 如果页面有主/副摄像头切换，两路都测试一下。

---

## 五、常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 页面打不开 | frpc 未启动 / 隧道未通 / 安全组未放行 | `systemctl status frpc.service`，检查 7000/2222/8080 端口 |
| 有页面但看不到画面 | FFmpeg 推流未启动或编号未改全 | 检查 `ffmpeg-stream.service` 状态，确认所有 `car0003` 都改成了 `car027` |
| 画面显示的是别人/其他车 | 官方子域多车共用或编号配置错误 | 用 `http://121.40.149.155:8080` 确认，再检查配置 |
| 摄像头打不开 | FFmpeg 推流服务占用摄像头 | 先停推流再测试，或重启推流服务 |
| 延迟高/卡顿 | 网络上行差 / 推流参数高 | 比赛走 5G 模块，开发可先用 WiFi 调试 |

## 七、注意事项

1. 修改 systemd 服务文件前**必须备份**。
2. 所有 `car0003` 都要改成 `car027`，漏改一个可能导致画面或控制异常。
3. 重启服务会短暂中断图传，属于正常现象。
4. 比赛遥控/图传阶段必须使用小车自带 4G/5G 模块，避免“使用局域网”判罚。
5. 如果修改后仍不正常，优先查看：
   ```bash
   systemctl status ffmpeg-stream.service
   systemctl status ffmpeg-stream-sub.service
   systemctl status frpc.service
   journalctl -u frpc.service -n 50
   ```
