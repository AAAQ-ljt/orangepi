# 自建服务器图传部署文档(无域名阶段 · 先用 IP 验证)

> 目标:不依赖官方域名 `carXXXX.smartcar.run`,用自购服务器 `121.40.149.155` 实现:
> 浏览器(局域网/公网)→ 自己的服务器 → FRP 隧道 → 小车 Web 服务(网页 + 控制指令 + 图传)。
> 当前阶段先用 **IP + 端口** 验证画面与控制,HTTPS 域名阶段见文末"阶段 5"。

---

## 现状与目标架构

```
浏览器
  │  http://121.40.149.155:8088   (Nginx 反代)
  ▼
服务器 121.40.149.155
  ├─ Nginx  :80(HTTP 反代)→ frps 隧道端口
  ├─ frps   :7000(隧道服务,已在运行 ✅)
  └─ Nginx-RTMP / HTTP-FLV  :1935 / :8089(视频入口,待装)
        ▲ ffmpeg 推流
        │
小车 OriginPi 5 (NAT 内网)
  ├─ frpc         :主动连服务器 7000,映射本地 Web 端口
  ├─ ffmpeg-stream:摄像头 RTSP → FLV 推到服务器视频入口
  └─ 网页 Web 服务(页面 + WebSocket 控制)
```

无域名阶段浏览器走 `http://IP:端口`,WebSocket 走 `ws://`(语音"按住说话"要等 HTTPS 阶段才能用,画面+控制不受影响)。

## 阶段 1:扩展 frps 允许小车 Web 端口(服务器端)

小车上的 frpc 会给 Web 服务申请一个 `remote_port`(比如 `7500`)。frps 默认允许任意端口,**如果配置里写了 `allowPorts`,要把小车 Web 端口加进去**。示例(frps.toml):

```toml
bindPort = 7000
token = "<和车上 frpc 一致>"
allowPorts = [{ start = 7000, end = 7999 }]   # 若已有此项,确保包含小车用的端口
```

然后重启:

```bash
systemctl restart frps && systemctl status frps
```

> 注意:你之前的方案里 `服务器:2222 → 小车:22` 能通,说明这套机制是好的。小车 Web 端口映射与它同理,只是 remote_port 不同。**当前 2222 不通是"小车端隧道掉线",不是服务器问题**(见文末故障排查)。

## 阶段 2:服务器装 Nginx + RTMP 模块(视频入口)

小车上的 FFmpeg 会把摄像头画面推上来,服务器需要能接收并转发给浏览器。

**Ubuntu/Debian:**

```bash
apt update && apt install -y nginx libnginx-mod-rtmp
```

**CentOS/Rocky:**

```bash
dnf install -y nginx
# CentOS 需自行编译或用 SRS,优先建议装 Ubuntu 系镜像;也可联系我换 SRS 方案
```

**配置 RTMP + HTTP-FLV**(编辑 `/etc/nginx/nginx.conf`,在文件末尾 `http {}` 块之外加):

```nginx
rtmp {
    server {
        listen 1935;
        chunk_size 4096;
        application live {
            live on;
            record off;
            allow publish 0.0.0.0/0;   # 推流入口(后续可限定只允许小车 IP)
            allow play 0.0.0.0/0;
        }
    }
}
```

在 `http {}` 块内加视频播放口(HTTP-FLV,浏览器 flv.js 直接能播):

```nginx
server {
    listen 8089;
    location /live {
        flv_live on;
        chunked_transfer_encoding on;
    }
}
```

```bash
nginx -t && systemctl restart nginx && systemctl status nginx
```

防火墙放行(阿里云还需在安全组放行):

```bash
ufw allow 1935/tcp; ufw allow 8089/tcp     # 或 firewall-cmd --add-port=1935/tcp --permanent ...
```

## 阶段 3:服务器 Nginx 反代小车网页(控制面)

把小车网页(页面 + WebSocket 控制)从隧道端口暴露到公网:

```nginx
server {
    listen 80;                    # 域名阶段会改 443
    server_name _;

    location / {
        proxy_pass http://127.0.0.1:7500;      # ← 小车 frpc 申请的 remote_port
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;              # WebSocket 长连接
    }
}
```

```bash
nginx -t && systemctl reload nginx
```

验证:浏览器打开 `http://121.40.149.155/`(若 80 被占,可改 listen 8088,访问 `http://121.40.149.155:8088`),应看到小车网页;状态栏 **WS:已连接** 即控制链路通了。

## 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| `ssh -p 2222` 连接被拒 | 小车端隧道掉线(关机/断网/frpc 停) | 小车上电联网;USB 串口线进系统后 `systemctl status frpc`、`systemctl restart frpc` |
| 网页能开,WS 未连接 | Nginx 缺 Upgrade 头 | 检查 `proxy_set_header Upgrade/Connection` |
| 画面黑屏 | 推流地址/流名不对,或 RTMP 模块没生效 | `nginx -t`;小车里 `systemctl status ffmpeg-stream`;服务器 `ss -tlnp | grep 1935` |
| 只有你自己能访问 | 阿里云/腾讯云安全组未放行 | 控制台安全组放行 80/1935/8089 等端口 |
