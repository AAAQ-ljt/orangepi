# **避障停车实验**

## **实验目的**

1、掌握 C++ 结合 OpenCV 在香橙派下 V4L 摄像头读取、图像采集保存的开发流程。

2、理解图像模板匹配算法matchTemplate原理，实现标志物视觉识别。

3、学会 PCA9685 舵机 / 电机驱动控制，完成小车识别标志物自动停车、无标志物自动巡航。

4、掌握 Linux 信号捕获、程序安全退出机制，避免电机失控、摄像头占用问题。

5、掌握后台推流服务启停逻辑，解决摄像头设备抢占冲突。

6、分两段程序分工：camera_save.cpp采集停车标志物样本图；park.cpp实时识别并控制小车启停。

## **实验内容**

1、编译运行camera_save.cpp：自动扫描 /dev/video0、/dev/video2 摄像头，窗口实时预览画面，按s键保存标志物图片至markers文件夹，ESC/Ctrl+C 安全退出。

2、使用采集工具拍摄多张停车标志物图像，作为识别模板素材。

3、编译运行park.cpp：自动加载markers文件夹全部灰度模板，实时摄像头画面缩放灰度预处理。

4、基于归一化相关系数模板匹配，设定匹配阈值 0.7，匹配达标控制电机停止；匹配不足电机正常行驶巡航。

5、实现多信号安全捕获（Ctrl+C、程序崩溃、kill、ESC 按键），退出时电机归零、释放 PCA9685、重启后台推流服务。

## **实验原理**

**（一）图像采集程序 camera_save.cpp 原理**

1、**V4L 摄像头读取**：VideoCapture(cam_id, CAP_V4L)使用 Linux 原生 V4L2 驱动读取摄像头，降低延迟。

2、**设备自动扫描**：遍历设备 0、2，自动检测可用摄像头，避免手动修改设备号。

3、**服务释放机制**：ffmpeg 推流服务会长期占用摄像头，程序启动前停止推流服务，结束后自动恢复，解决设备忙报错。

4、**图像保存逻辑**：按下s键自动编号保存 JPG 至 markers 目录，自动创建文件夹。

**（**二**）视觉停车识别程序 park.cpp 原理**

1、**PCA9685 驱动**：通过脉冲宽度控制电机转速、舵机角度，定义高速巡航脉冲SPEED_RUN=1670、停止脉冲SPEED_STOP=1600。

2、**模板匹配算法 matchTemplate**

使用TM_CCOEFF_NORMED归一化相关系数匹配，返回 0~1 匹配分数；分数越高代表画面与模板相似度越高。设置阈值0.7作为识别判定标准

3、**图像预处理加速**

原图缩小至 160×120 并转为灰度图，大幅减少计算量，提升识别帧率。模板统一缩小 50% 加载，降低匹配耗时。

4、**状态锁防重复播报**

etected_flag标志位，仅在目标出现 / 消失瞬间播报一次，避免循环刷屏。

5 **多信号安全退出** 

绑定 SIGINT/SIGTERM/SIGABRT/SIGQUIT 全部异常信号，无论何种退出方式都停止电机、释放 PCA9685、重启后台服务。

**七****、实验现象**

无标志物：匹配分数低于0.7，电机持续巡航，终端播报“系统启动，开始巡航”。

## **实验结果**

1、采集程序camera_save可自动识别摄像头，实时预览画面，按键s成功保存多张标志物图片至 markers 目录。

2、停车程序可自动加载全部采集模板，画面左上角实时打印当前匹配相似度分数。

3、标志物进入画面时匹配分数≥0.7，小车电机立即停止；标志物移出画面，电机自动恢复行驶，播报提示正常输出。

4、任意方式退出程序，电机自动归零停止，PCA9685 资源释放，ffmpeg 推流服务自动恢复，无摄像头 / 硬件占用故障。

## **结果分析**

1、 **分程序设计优势**

图像采集与识别分离，先批量采集多角度样本再进行匹配，大幅提升识别准确率；若直接单张模板，标志物偏移、缩放后容易识别失败。

2、 **模板匹配算法优缺点**

优点：实现简单、计算量小、嵌入式香橙派可实时运行；缺点：对标志物旋转、光照剧烈变化鲁棒性差，适合固定场景停车识别。

3、 **服务启停必要性**

Linux 下同一摄像头只能被一个程序占用，ffmpeg 推流后台常驻会抢占设备，因此采集 / 识别程序启动前必须停止推流，结束后恢复。 

4、 **信号捕获安全机制意义**

嵌入式小车无人工紧急刹车，若直接强制 kill 程序，电机保持通电会持续行驶；信号捕获保证任何退出场景电机都归零停止，保障硬件安全。
