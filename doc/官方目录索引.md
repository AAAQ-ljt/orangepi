## 2026-10-08 串口复查（阶段 0 参考笔记，只读）

> 通过串口（orangepi5 旧车）逐一核对，**只读**未做任何改动。串口登录为 `orangepi` 用户，
> 读 root 文件需 `echo orangepi | sudo -S <cmd>`（免交互；不能用交互 sudo，会卡住会话）。

| 检查项 | 结果 |
|---|---|
| 主机名 | `orangepi5`（旧车） |
| 运行态 | 手动遥控模式（上电默认），负载 3.8x，温度 38.8°C，opi-control / talk-player / nginx 均 active，无自动驾驶进程 |
| 代码同步 | `/root/dev` 与仓库 **md5 全一致**：lane_ref.py / start_gate.py / lane_control.py / settings.py |
| `site.yaml` | `servo_center_angle: 86.5`、`steer_sign: -1`、`target_x: 375.0`、**`lane_roi_top_ratio: 0.25`、`lane_roi_bottom_margin: 24`（→ ROI y120~456，与本地默认 0.35/200 不同，跑 sweep 对照时以车上值为准）**、`arbiter_conf_thresh: 0.28` |
| 模型 | `/root/dev/models/`：`best11nseg.rknn`（上届 9 类）+ `best_4cls_640x480_fp16.rknn`（4 类）；无 8 类 → 模型轨产出后上板 |
| 官方目录 | car_Tracking（`line_follow.cpp` 黑线质心循迹 KP7/KD3 + `pca9685.c + pid.c`，`SERVO_MID_US + pid_out`）、ParkingVision（`park.cpp/park2.c/park.py` 模板匹配避障停车，320×240 摄像头 0，`find_target` 命中即停 SPEED_STOP、消失即 SPEED_RUN）、car_Keyboard_Control / car_Navigation / opi-control / SIM8200_for_RPI / hardware_Test 均在位 |
| 串口注意 | 登录用户是 `orangepi` 不是 root（serial_car.py 的 root/orangepi 假定不适用于这台车现状）；仍严格遵守"不发 Ctrl+C"（FIQ Debugger） |

**结论**：车端代码与仓库同步、标定在位；官方目录全部仅作参考（line_follow.cpp 即 4 套循迹方案#1，
park2 模板匹配为本届不采用的方案，仅存档）。下次操场前的例行核对命令：
`sudo bash /root/dev/scripts/car-mode.sh status`、`sudo ls /root/dev/models/`、查启动日志 `[site]` 行。
