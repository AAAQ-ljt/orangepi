## 2.5 循迹扫线实跑（蓝板发车 → 循迹 → 再见蓝板停车）

**摄像头固定用下摄 `--camera 2`（云台不参与巡线）**。⚠️ **循迹档已统一到 §2.6 的
`lane_ref_test.py`**：`bench_test.py` 的扫线档随两条旧扫线模块一起归档了，现在它只保留
"转向方向 / 直行基准 / 蓝板发车 / 速度标定"这些**不依赖扫线**的项（见 §2 表格）。

板在车前 → 停（1500us）；移开 → 循迹；再放回正前方 → 停（**移开可以再发一次**）。
**板要摆在下摄的正前方**——发车与停车用的都是下摄这一路画面。

```bash
# ① 先不动电机：确认板能被认到、线能扫到、自检能不能选到带
sudo python3 /root/dev/scripts/lane_ref_test.py --no-motor --max-seconds 60

# ② 正式跑（详细算法与调参见 §2.6）
sudo python3 /root/dev/scripts/lane_ref_test.py --allow-motion --max-seconds 120
```

**判据与调参对照表**（跑完看终端状态行 + 会话目录里的 `summary.json`/CSV）：

| 现象 | 看哪个数 | 怎么调 |
|---|---|---|
| 车不动 | 阶段一直是 `(stop)`，或结尾出现"⚠️ 全程没见过蓝板" | 板没被认到：换更大的板 / 摆到下摄正前方更近处；先用 `lane_probe` 确认画面里蓝色占比 |
| 自检说"所有候选带都锁不到两条线" | 自检 ① 的候选带表全是有中心 0/n | 先按 §1 解决扫线（压镜头角度）；自检会保留配置值继续跑 |
| 移开板后拱一下就停 | 阶段 `(acquire)` 3s 后变 `(lost)` | 探路窗口里没找到线 → 先按 §1 解决扫线；确需更久可 `--acquire-s 5` |
| 跑一段后突然停 | 阶段 `(lost)` + 打印"丢线 x.x s 没恢复" | 线真的丢了（丢线维持 `--hold-s` 默认 0.6s）；把 `--hold-s 1.0` 会更"敢赌" |
| 过弯切内道 / 压线 | 误差大时舵机角度不够 | `--kp 0.2`（默认 0.15）、必要时 `--limit-deg 20` |
| 蛇形 / 画龙 | 误差在正负之间来回过冲 | `--kd` 加大（0.12 → 0.3）、`--kp` 调小 |
| 越修越偏（冲出赛道） | 误差单调变大 | **转向方向反了** → `config/site.yaml` 写 `steer_sign: -1`；先用 §2.1 的 `--steer-test` 确认 |
| 速度不合适 | 状态行的 `电调=xxxx us` | 默认 1560（直道 1560 / 大误差 1550）；要更快改 `--speed-us`（死区 1545，调试上限 1600），想保留"直道提速"用 `--speed-fast 15` |

> ⚠️ 跑之前确认：场地空旷、有人在旁能立刻断电；`--max-seconds` 是硬上限；
> 任何退出方式（Ctrl-C / 超时 / 出错）都会**电调归零 + 恢复远程控制阶段**。
> 脚本运行期间**两路推流都会被停掉**（摄像头独占），浏览器看不到画面，靠终端状态行 +
> 会话目录里的图/CSV 复盘（**每跑一次都把这些拉回本地**，见 §2.6）。

## 2.6 参考实现版循迹（`lane_ref_test.py`，推荐先跑这个）

严格按参考实现（`oldCode/src/vision/vision.cpp` + `control.cpp`）写的脚本，不掺我们自己的启发式；
仓库里另外两套扫线（`lane_scan.py` / `lane_hough.py`）已归档到 `dev/attic/`。
检测器在 `vision/lane_ref.py`、控制在 `control/lane_control.py`，`lane_probe` 与它**共用同一个检测器**
（读数不一致就说明配置没对齐；现在 ROI 只有 `config/site.yaml` 一处来源）。

**2026-09-21 重构后，现场流程是"一条命令 + 按提示挡板"**：

```bash
# 只分析一张图（本地也能跑，不碰硬件）
python scripts/lane_ref_test.py --image 某张赛道图.jpg

# 复盘上次实跑的落盘数据（本地；可换参数重跑检测与控制律）
python scripts/lane_ref_test.py --replay logs/lane_20260922_101500 --roi-sweep --kp 0.2

# 车上：只看读数，不动电机
sudo python3 /root/dev/scripts/lane_ref_test.py --no-motor --max-seconds 60

# 车上：正式跑
sudo python3 /root/dev/scripts/lane_ref_test.py --allow-motion --max-seconds 120
```

**现场操作顺序（照做，别跳）**：

1. 车摆正在车道里（这一步决定了自动标定的目标点准不准）；
2. **先别挡板**，启动脚本 → 它会打印
   `① 候选带扫描（N 帧静止画面）` 表、`② 自动前瞻带`、`③ 自动标定目标点`、`④ 镜头朝向体检`，
   并把选中的带与目标点写回 `config/site.yaml`（下次直接用）；
3. 看到 `✅ 起步前自检完成` → **把蓝板挡到下摄正前方** → 看到 `✅ 已确认蓝板`；
4. **移开板** → `🚗 发车` → 车按 `track` 走；
5. **再挡回板** → 立刻停车（`🛑 再见板 → 停车`）；移开板还能再发一次（计时与 PID 会重置）；
6. 结束（Ctrl-C 或 `--max-seconds` 到）后，把会话目录拉回本地：
   `python scripts/ssh_get.py -r /root/dev/logs/lane_<时间戳> .`

**开跑前那条硬规矩**：自检打印 `⚠️ 证据偏弱（最长连续支持只有 NN 行 < 20）` 就**别跑**——
2026-09-22 落地实测，车摆偏时自检把目标标成 417/291（真值约 341），车就照着错目标跑；
现在脚本在这时会**拒绝采纳**自检值、保留 `site.yaml` 的旧值，但最该做的还是**把车重新摆正再跑一次**。

**怎么读自检那张候选带表**（这是判断"这片场地到底能不能做白线循迹"的第一手证据）：

| 列 | 含义 | 好/坏 |
|---|---|---|
| 有中心 | 这一档 ROI 下，有几帧能算出可信中心 | **必须 `n/n`**；只有部分帧说明不稳定 |
| **连续支持** | 拟合出的两条线**最长连续多少行**底下真有边缘（= 它是一整条线还是几段碎边） | **这是最灵的一列，也是"该不该开跑"的判据**：**≥30 行**才放心跑；12~20 行属于弱证据（脚本会拒绝采纳并提示重新摆车）；几行的基本是反光/碎边被拟合出来的。2026-09-22 实验室实测：车摆正那次 58 行，摆偏的两次 12~40 行 |
| 支持行占比 | 支持行 / "两条线都在画面内"的行 | 参考值，别单独用它下结论（分母受画面内容影响） |
| 中心跨距 | 有中心那几帧的中心极差（车没动！） | **>25px 就是"证据弱"**：脚本会拒绝采纳目标点并提示重新摆车（2026-09-22 实测：74/166/90px 的三次，目标点被写成 318/348/354 每次都不一样的罪魁祸首） |
| 质量 | 该档的质量中位数 | 越接近 1 越好；<0.28 控制层不会跟线 |

**算法（照抄参考实现，§4.4 登记的偏离除外）**：ROI → 灰度 → 高斯 → **Canny(60,140，按边缘数
自适应并钳位）** → **HoughLinesP(1,3°,50,30,5)** → 斜率 |dy/dx| ∈ [0.25,2] → 按斜率符号分左右、
每侧取代表线 → 前瞻带（**绝对行号**，默认 y 168~230）逐行求中点平均 → error（像素）
→ `angle = 90 + sign·(kp·e + ki·∫e + kd·Δe)`（kp/ki/kd = 0.15/0.01/0.12，限幅 ±15°，
输出再平滑 0.7/0.3）→ 误差大时自动减速。

**本轮按我们车改过/补上的地方（都写在《循迹脚本交接.md》§4.4，共 8 条）**，现场最相关的四条：

- **单侧丢线不再等于停车**：丢一侧时用**车道半宽先验**（两侧都在时实测）推中心，质量 0.55 档
  （会降速但继续走）；`--no-single` 可退回"单侧不给中心"的保守行为；
- **丢线阶梯**：丢线 0.6s 内沿用上次中心（误差按时间衰减回中位）并减速，超时停车（`--hold-s`）；
- **ROI 与前瞻带都自动选**（`--no-auto-roi` / `--no-auto-look` 可关），默认值取 `config/site.yaml`；
- **速度**：基准 `--speed-us 1560`（2026-09-20 现场实测 1575 太快），自适应只减速不提速
  （`--speed-fast 0`），且减速/维持档有死区下限（1550）不会掉进死区停车。

调参（不用改代码）：`--kp/--ki/--kd --limit-deg --target-ratio --roi-top/--roi-bottom-ratio
--look-top/--look-bottom --pick steepest|longest --speed-us --speed-fast --speed-slow
--acquire-s --hold-s --min-quality --single-mode width|border|off --gains literal|width`。

**对照实验（回答"是我们的改动错了，还是镜头不行"）**：

```bash
# 按参考实现 oldCode 的原样跑（它 320×240：ROI 0.50~0.85、算中心的行 130~230、
# 目标点=画面中心、单侧代画面边界、增益按画面换算），自检全部关掉
sudo python3 /root/dev/scripts/lane_ref_test.py --no-motor --ref-behavior --max-seconds 60
```

看两件事：① 候选带表里**参考那一档**（0.50~0.85）的『支持行占比』；② 它的 y 范围。
参考能工作是因为它的镜头**看得见近处地面**（所以敢用 y 0.54~0.96 那一段）；我们的下摄太平、
近处是画外 → 若那一档的支持行占比很低、或算出来的线是外推的，就说明**是视角的锅，不是改动的锅**。
对照表（每个环节"要 1:1 复现该用哪个参数"）在《循迹脚本交接.md》§4.5。
