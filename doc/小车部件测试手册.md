# 小车部件测试手册 v1.0

> 适用：OrangePi5（RK3588S）+ XT-NetRC 底盘（2026 智能车）
> 测试方式分级：**Phase 0**（SSH 自动只读）/ **Phase 1**（摄像头抓帧，自动）/ **Phase 2**（需人工在场的安全/运动测试）
> 配套脚本：车端 `/root/car-test/test_all.sh`（本地副本 `scripts/car-test/test_all.sh`）
> 全程原则：**先记录原值再改动；运动测试前车轮悬空/车头朝无人区；先稳后快**

## Phase 1：摄像头画面核验（推流链路）

> 前置：Phase 0 全绿。网页本身也可验（见 T12）。

1. 确认推流进程：`pgrep -af 'ffmpeg.*rtsp'` → 应见 `rtsp://82.157.204.126:17005/cam_car0003`（主）+ `/cam_car0003_sub`（副）
2. 浏览器打开 **http://121.40.149.155:8080/** 或官方 car0003 页面 → 应看到实时画面
3. 画面延迟粗测：手机秒表与画面时钟对照（<1s 正常，>2s 需排查）
4. 双摄像头确认：页面若有主/副切换按钮，两路都试

## Phase 2：交互与运动测试（人工在场）

### T12 网页控制台（最快的外设总测）
1. 浏览器打开 8080 页面
2. **解锁**后依次测试：转向舵机 / 油门（悬空）/ 云台水平 / 云台垂直
3. **按住说话**功能（需官方域名入口；8080/IP 直连不支持按官方教程）
4. 判定：部件响应连续、无卡顿；WS 状态显示已连接
   - ⚠️ WS 断开 + 摇杆失灵 → 查 9001（`systemctl status` 无则缺依赖/T4-6）

### T13 转向舵机标定（通道 0，接线图：PCA9685 CH0）
1. 舵机臂拆下再测（防堵转）
2. 手动发脉宽：500/1500/2500µs 应分别对应左/中/右
3. 记录中点脉宽与限幅（写回 config/hardware.yaml）
4. 判定：无抖动异响、限位正确

### T14 电调解锁与油门（通道 1）——⚠️ 最高风险项
1. 车轮悬空、电调电池接好、急停可用
2. 上电确认默认 0 油门；执行解锁时序（中位→最低，听到蜂鸣确认音）
3. 缓慢推油门 → 轮子转 → 回中停止
4. 判定：解锁一次成功、回中即停、无窜动

### T15 云台范围测试（通道 2/3）
1. 水平 0→180°、垂直 0→180° 扫一遍
2. 判定：无卡死异响、回中点稳定

## 常见故障快速定位表（今日实战复盘）

| 现象 | 原因 | 处理 |
|---|---|---|
| 网页打开但摇杆全失效 / WS 已断开 | 9001 崩溃（缺 adafruit_pca9685） | `pip3 install adafruit-circuitpython-pca9685` + 重启该服务 |
| 摄像头打不开 | ffmpeg 推流占用独占设备 | 先 `systemctl stop ffmpeg-stream.service`（测完恢复） |
| frp 2222/8080 不通 | 小车断网 / frpc-ssh 未注册 | 查 `systemctl is-active frpc-ssh`；等 5s 自动重连 |
| 蜂窝 wwan0 无 IP | car-dial 未起 / APN 不对 | `systemctl restart car-dial`；APN=cmnet |
| SIM 不识别 | 卡没插到位 / 槽位错 | 重插卡、换槽、重启（CPIN READY 才算） |
| 官方 car0003 画面是他车 | 官方子域多车共用/路由错 | 用 8080 入口 + 记录证据问官方群 |
| 推流画面卡顿 | 蜂窝/热点上行差 | 比赛走 5G 模块；开发走 WiFi；建 `pool_count=5` |
