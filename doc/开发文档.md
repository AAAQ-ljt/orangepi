## 0. 三十秒现状

**项目**：2026 全国大学生智能汽车竞赛 · 室外 5G 远程驾驶无人车赛。Orange Pi 5（RK3588S）+ XT-NetRC 阿克曼底盘 + PCA9685 + 双摄（`/dev/video0`=icspring **云台主摄**（红绿灯用）/`/dev/video2`=Global Shutter **下摄（巡线固定用这一路）**）+ SIM8200 5G。
**目标**：完赛，尽量快。规则致命项：**停车超 20s 不动 = 比赛失败**；罚时：压线 +10s/次、撞锥 +20s、停错/无轮入区 +100s、抢灯 +20s、未停 +50s；**红绿灯等待时长不计入 T有效 → 该等就等**。可靠性优先于速度。

### 1.2 双通道融合规则（方案核心）

> 模型通道未就绪时，该元素自动退化为颜色单通道——**单通道永远是合法运行态**；模型到位后升级为双通道校验。

| 元素 | 颜色/几何通道（主，现场可调） | 模型通道（仅灯） | 融合规则 |
|---|---|---|---|
| 发车 | HSV 边沿（已实现） | — | 挡板不进模型 |
| 循迹 | Canny+Hough（4 方案选型后） | — | 模型不参与（车道/分割轨放弃） |
| 斑马线 | 灰度>180 二值化、连通域面积>200 且 ≥4 | — | 纯颜色通道（官方验） |
| 红绿灯 | HSV 红绿互比（H 0-10∪170-180 / 35-85、面积≥500、红>绿）+ 分区二次校验（左 1/3 红 / 右 1/3 绿）、3 帧去抖 | **light3cls**: off/red/green | **两者一致才动作**；不一致→unknown 维持停车（防抢灯）；模型未就绪→HSV 单通道 |
| 锥桶 | HSV+锥度先验+接地点+决策树 | — | 纯颜色通道；防漏检优先（撞锥 +20s） |
| 停车区 | 黄区 HSV 面积≥2500 + 蓝板 HSV 接地点 + **黄区外框中点 vs 蓝板底边中点判左右**（几何，多帧锁定） | — | 纯几何通道；"远距预减速"由 HSV 黄区前向 ROI 检出替代（~~A/B 凸包比~~：2025 上届"停车标志牌"遗产，本届规则只有挡板遮挡机制，不用它） |

## 2. 元素设计（判据 / 阈值 / 验收）

### 2.1 发车（P0-2 ✅）

- **判据**：蓝板（HSV 蓝色占比 + 近距离大块失焦 + 移板瞬间帧差）。**必须边沿触发**（`vision/start_gate.py`）：
  先确认遮挡（连续 3 帧）→ 武装 → 再等遮挡消失（连续 5 帧）→ 放行。绝不用"当前无遮挡"直接发车（防上电即冲）。
- **FSM 侧独立复核同一逻辑**（不盲信视觉闩锁）；超时只告警不放行。
- 现场标定：`START_BLUE_RATIO_THRESH`（10-10 执行单复验 5/5）。
- 板要摆在下摄正前方、够大够近；跑前查启动日志 `[site]` 行。
- **★ 2026-10-15 修复（车盖误判，见 §7）**：镜头压低不够时**车自己车盖的上沿**会落进 ROI，那圈暗蓝灰像素
  面积 0.06~0.14、主导度只有 12~18，**压着 0.06 阈值抖** → 两次"没放板就发车"。修法 = `START_GATE_ROI` 底边
  0.95→0.80（A）+ 面积路径**也要主导度≥35**（B，新增 `START_BLUE_AREA_THRESH_BIG=0.20`）+ 画面裁剪
  (`FRAME_CROP_LINE_Y=384`)。当场 30 次武装实测：面积 0.108~0.999、主导度 97~136，**零假报**。

### 2.2 循迹（P1-1 ✅ 代码级；视角限制 → 非完赛路径依赖）

> **★ 唯一循迹方案（2026-10-14 更新；旧版见下方历史）**：**`dev/scripts/lane_final_test.py`**（单文件最终版：

> `train/opencv-level1/lane_test/1014_lane_final/report.md`（全片双侧 82%、剔除末段 89%、丢失 0%、中心 p90 5.8px）。
> 旧的一整套（`lane_ref_test.py` / `lane_official.py` / `centroid_follow.py`）**已归档**
> （`archive/20261014-lane-scripts/` + `dev/attic/lane-old-20261014.tar.gz`），下文相关记录保留为历史。
>
> **★ 唯一循迹方案（2026-10-11 收敛定案，已被 10-14 取代）**：`lane_ref.py` 边缘法（2026 户外赛官方
> `双线循迹代码.txt` 同源，逐参数一致）。其余循迹代码**全部搁置**：
> `lane_scan` / `lane_hough`（旧版，已进 attic）、`centroid_follow` ②③（操场实测
> 反光拉偏质心，淘汰）、`lane4schemes_probe`（仅留作离线对照工具，不扩展）。
> 2025 上届 opencv 版 `image_handle2`（逐行扫线 + 单侧代边界 + 加权误差）已通读，
> 作为"若 Hough 方案仍不可用"的参考笔记（其 320×96 窄图 + 灰度自适应预处理与本车
> 反光环境不直接兼容，现阶段不实现）。
>
> **★★ 帧率更正（2026-10-15，优先级最高）**：10-12 记的"下摄模组只有 15fps / 瓶颈不在代码或读取方式"
> **是错的**——真凶是 cv2 的 `CAP_PROP_BUFFERSIZE=1` 把驱动砍半（同一设备实测 **14.1 vs 28.0fps**，
> ffmpeg 走同一设备一直是 **29.8**）。`camera_guard.open_camera()` 已修（不设 BUFFERSIZE + 显式 FPS=30）→
> 循迹主循环 **14.7 → 29.9fps**。控制律是"15fps 登记 + 按实测 dt 折算"，**手感不变**（rate.py 的设计点）。
>
> **★★ 增益现场结论（2026-10-15，22 趟真跑；详见 §7）**：亮光下 **`kp 0.10 + kd 0.50 @ 1585`** 最稳
> （`|err|`p90 33、抖动 |Δ舵角|/帧 p90 1.0°、饱和 0%、guard 0），但同参数另一趟触发过 →
> **1590 以上还没证明能持续跑**；**kd ≥0.65 会 D 过载**（抖动 9°+/帧、饱和 7%+ → 画龙保护）。
> 判定三件套（`scripts/diag/lane_ab_summary.py`）：`guard` = 0、抖动 p90 <3°、`|err|`p90 别反弹（反弹=kp 太小）。
> **暗光（AE 长曝光 16.6fps）是独立退化因素**：同参数抖动翻 3~5 倍 → 天黑降速，别在暗光下判高速档。
> 上届参考换算（640px 口径）：等效 kp≈0.10/0.125、kd≈0.19~0.30。
>
> **★ 帧率结论（2026-10-12 定案，取代 10-11 的"锁 15FPS"；上面的更正优先）**：下摄的**真实出帧率随光照变**
> ——亮环境 MJPG 实测 **29.8fps**（跑满），暗环境 AE 拉长曝光（33/60/120ms 台阶）掉到
> **16.7 / 8.3fps**，即 9~30fps 区间；`lane_ref` 检测单帧仅 3.7ms，处理不是瓶颈。
> **因此控制律改成"按实测 dt 折算"，不再锁定某一个帧率**（2026-10-12 落地）：
> 所有增益/窗口的**登记口径 = 15fps**（现场整定时的帧率），运行时按实测 dt 折成连续时间
> 等价形式（`control/rate.py`）：
> · 积分 = ki×15×∫e·dt（**每秒动作不变**；30fps 下逐帧等效 ki 自动减半 0.02→0.01）；
> · 微分 = kd/15×(de/dt)（**等效连续阻尼不变**；30fps 下逐帧等效 kd 自动加倍 0.12→0.24）；
> · 输出平滑按时间常数折算（15fps 的 0.7 ↔ 30fps 的 0.452）、Δe 钳位按 px/s（300px/s）；
> · 滤波窗口/防抖帧数按秒折算（窗口 5 帧@15fps = 10 帧@30fps）。
> **现场 A/B 表继续按 15fps 口径写数字**（0.06 / 0.12 起步 / 0.24），代码自己折算——
> 换帧率不再需要重标 kp/kd。旧结论"ki ×2 要手写在增益里""kd 不折算"已作废。

- **入口/检测（2026-10-14 起）**：`scripts/lane_final_test.py`（**最终循迹入口**：脊搜索检测 + PD 控制 + 记录 + 安全；离线 `--image/--frames/--video/--calibrate`，在线 `--no-motor/--allow-motion`）；复用 `control/lane_control.py`（PidRef/护栏）+ `filters.py` + `rate.py`。A 路径（main 那条线）仍用 `vision/lane_ref.py`。旧入口 `lane_ref_test.py` 已归档（`archive/20261014-lane-scripts/`）。

- **算法链路**（lane_ref，与官方 2026 室外赛 demo 逐参数一致）：
  ROI（默认取 site.yaml）→ 灰度 → GaussianBlur(5,5,σ0.5) → Canny(60,140，**同帧自适应**钳位 low∈[20,160]/high∈[40,320]) → HoughLinesP(rho=1, θ=3°, thr=50, minLen=30, maxGap=5) → 斜率先验 |dy/dx|∈[0.25, 2.0] → 按斜率分左右+位置锚定 → 每侧选代表线（--pick steepest/longest）→ 配对宽度闸门（现场定稿 **120/500**；外加"两条代表线在 y_ref 必须落画面内 ±30px"兜底）→ 前瞻带（**自动定到 y≈120~168**，见 §6.4）内逐行取中点平均 → `error = center_x − target`。
- **单侧丢线**：`center = 可见侧 x ± 半宽`（WidthPrior 实测中位数/窗口 15 帧@15fps，按实测帧率折成同样 1.0s——30fps → 30 帧）；种子半宽质量压 0.25（<阈值→按维持处理）；推出画面外的中心丢弃。
- **控制**：ErrorFilter（窗口 5 帧@15fps、离群 60px=15 误差单位×4；窗口按实测帧率折算）→ PID kp0.15/**ki0.02**/**kd0.12**（**15fps 登记口径**，运行时按实测 dt 折算）限幅±15° 平滑 0.7（现场 A 档用 0.6；30fps 下等效 alpha 0.452）→ `angle = center_deg(86.5) + sign×pid`（`site.yaml steer_sign: -1` 实测正确：角度大=左转；中位是 `servo_center_angle` 而非写死的 90）。
- **速度**：基准 1560us（10-11 现场提速档 **1580**）；|e|<5 → +0；|e|≥15 → −10；**硬下限 = 死区 1545 + 5 = 1550us**（低于死区车从减速变停车）；`--single-hold` 丢线保速直行。
- **护栏（不可删）**：单侧兜底帧 ±5°、弱对帧（一侧≤2段）±10°、画龙（2s 内 3 次 ≥12° 大幅摆动→停车）、跑偏（滤波后误差 ≥60px 持续 1.5s + 同时看原始误差，0=关闭）。
- **丢线阶梯**：质量<min-quality(0.28) → hold 0.6s（沿用上次中心、误差衰减回中位、减速）→ 仍无读数 → 停车；发车后 3s 内一次没见过线 → 低速探路 → 再没有 → 停车。

### 2.4 红绿灯（双通道主线）

- **规则与场地**：赛事方在距灯 **1m** 处的跑道侧面放光敏传感器 → 车经过触发 → 灯变红 → 停车等待 → 绿灯通过。灯**横排三灯珠**（红-黄-绿）、赛道上方居中、离地 40cm、"灭灯"=三珠全灭。停车区 = 传感器与灯之间区域，X 轴不得超。

### 2.6 停车（P1-4）

- **几何先验法（v2.3 定案，不怕裁判怎么放）**：
  1. `parking_area` 标**整个黄色胶布长方形一个框**（不分成两格——分割线可能被板盖住）；
  2. **中间分割线 = 外框水平中点，在 IPM 俯视图里算**（图像中点 ≠ 地面中点，不做 IPM 必判错）；
  3. **蓝板底边中点（接地线）→ IPM → `board_x`**；在俯视图中与中线比：左半被挡 → 停右半格；目标点 = 空闲半格几何中心；
  4. 近距用 HSV 黄线横向对准（ROI 只在 PARKING 状态启用），纵向黄线 y + 里程（**无编码器 → 时间/IMU 推算，精度差一档**）。
- **参考系双保险**：A. 停车区外框（推荐，外框可见时）；B. 赛道左右边界归一化 `ratio=(cx−x_left)/(x_right−x_left)`（外框不可见时兜底；停车区偏一侧时阈值必须现场标定）。**禁止** `cx < 图像宽/2` 判左右（斜进必错）。
- **降级链**：外框+蓝板（主路径）→ 仅一侧外框边（宽度先验补）→ 单框无板（停它）→ 框内有板（取镜像半格）→ 板压中线 ±容差（用底边横向占用范围判，仍不定回溯更远帧）→ 黄胶布完全不可见（低速搜索+超时保守停）。
- **五阶段**：APPROACH（减速接近）→ SLOT_CONFIRM（连续 7 帧投票+置信度+排除不确定区，**锁定后不切换**）→ ALIGN_TO_SLOT（车位中心线，Pure Pursuit/Stanley/带前馈 PID；**不用检测框直接驱动舵机**）→ ENTER_SLOT（低速入库+限舵角变化率）→ FINAL_STOP（黄线+里程联合判断四轮入区）。
- 场地事实（规则初稿插图已核对）：停车区 = 1m（沿行驶方向）×赛道宽，赛道中线黄胶带分两格，**相对行驶方向左右并排**；蓝板挡在**入口边**。选择"早"：3~5m 一次性决策锁定。
- 验收：板在上格停下面 5/5、四轮入区不压线。

### 2.7 IMU（JY901S）

- **驱动**（`hardware/imu.py`）：UART `/dev/ttyS0` B9600、11 字节帧 `0x55 CID 8B SUM` + 校验和、四通道解码（acc/2048、gyro/16、姿态×0.01、**yaw 无符号 0~360**）、读前 tcflush 抢最新；静态零偏标定 100 样（`acc_bias_z=az−1.0`）；静止判据 |g|<2°/s；无硬件自动降级。
- **用法**：直行纠偏（与 servo_center 互补）、S 弯后方向恢复、仲裁"短时维持 0.3~0.8s"、停车对齐；回正闭环（init_yaw±13~20°、P=30、|误差|<1.5° 连续 3 帧、40s 超时）；**IMU 不可用显式降级开环**。
- 10-10 现场：实机验证接线/波特率（yaw 稳定、静止 az≈1.00g）；failed→B9600→115200 对调检查。

| 风险 | 应对 |
|---|---|
| 车停止超 20s = 失败 | 所有等待/停车都有超时兜底；红灯长等口径 P0-4 确认 |

| 模型与扫线抢 NPU（v11 只剩灯模型） | `--detect-every` 降频；单一推理线程+任务队列 |
| 程序异常退出导致车继续跑 | 全部退出路径统一安全信封（bench_common + car-mode.sh），见 §1.3 |
| 5G/网络断连 | 蜂窝优先+WiFi 账本+串口救援（见 `车端网络方案.md`） |

### 2026-10-12：循迹控制律**帧率折算**落地（15fps 锁定 → 按实测帧率）
