## 0. 三十秒现状

**项目**：2026 全国大学生智能汽车竞赛 · 室外 5G 远程驾驶无人车赛。Orange Pi 5（RK3588S）+ XT-NetRC 阿克曼底盘 + PCA9685 + 双摄（`/dev/video0`=icspring **云台主摄**（红绿灯用）/`/dev/video2`=Global Shutter **下摄（巡线固定用这一路）**）+ SIM8200 5G。
**目标**：完赛，尽量快。规则致命项：**停车超 20s 不动 = 比赛失败**；罚时：压线 +10s/次、撞锥 +20s、停错/无轮入区 +100s、抢灯 +20s、未停 +50s；**红绿灯等待时长不计入 T有效 → 该等就等**。可靠性优先于速度。

### 1.2 双通道融合规则（方案核心）

> 模型通道未就绪时，该元素自动退化为颜色单通道——**单通道永远是合法运行态**；模型到位后升级为双通道校验。

| 元素 | 颜色/几何通道（主，现场可调） | 模型通道（仅灯） | 融合规则 |
|---|---|---|---|
| 发车 | HSV 边沿（已实现） | — | 挡板不进模型 |
| 循迹 | Canny+Hough（4 方案选型后） | — | 模型不参与（车道/分割轨放弃） |
| 斑马线 | 灰度>180 二值化、连通域面积>200 且 ≥4 | — | 纯颜色通道（官方验） |
| 红绿灯 | HSV 红绿互比（H 0-10∪170-180 / 35-85、面积≥500、红>绿）+ 分区二次校验（左 1/3 红 / 右 1/3 绿）、3 帧去抖 | **light3cls**: off/red/green | **两者一致才动作**；不一致→unknown 维持停车（防抢灯）；模型未就绪→HSV 单通道 |
| 锥桶 | HSV+锥度先验+接地点+决策树 | — | 纯颜色通道；防漏检优先（撞锥 +20s） |
| 停车区 | 黄区 HSV 面积≥2500 + 蓝板 HSV 接地点 + **黄区外框中点 vs 蓝板底边中点判左右**（几何，多帧锁定） | — | 纯几何通道；"远距预减速"由 HSV 黄区前向 ROI 检出替代（~~A/B 凸包比~~：2025 上届"停车标志牌"遗产，本届规则只有挡板遮挡机制，不用它） |

## 2. 元素设计（判据 / 阈值 / 验收）

### 2.1 发车（P0-2 ✅）

- **判据**：蓝板（HSV 蓝色占比 + 近距离大块失焦 + 移板瞬间帧差）。**必须边沿触发**（`vision/start_gate.py`）：
  先确认遮挡（连续 3 帧）→ 武装 → 再等遮挡消失（连续 5 帧）→ 放行。绝不用"当前无遮挡"直接发车（防上电即冲）。
- **FSM 侧独立复核同一逻辑**（不盲信视觉闩锁）；超时只告警不放行。
- ⚠️ **闸门是"一次性闩锁"：发车后不再看板**（2026-10-16 文档更正，实现不动）：`lane_final_test.py` 里
  `allowed` 置位后就不再调 `gate.update()`，所以**没有"再见板即停"**。现场"把板挡回去能停"是另一条链路
  ——板挡住下摄 → 读数失效 → 丢线维持 0.6s → 按丢线停车（**还会往前滑一段**）。想立刻停：见 §7 的
  2026-10-17 条目（首选**停止文件** `touch /dev/shm/lane_stop`；其次 `stop_run.sh`；Ctrl+C 只在
  「该进程就是这个终端的前台作业」时才到得了车）。
  （台架 `bench_test.py` 是另一种语义，它确实"再见板→停"，别把两者混起来讲。）
- 现场标定：`START_BLUE_RATIO_THRESH`（10-10 执行单复验 5/5）。
- 板要摆在下摄正前方、够大够近；跑前查启动日志 `[site]` 行。
- **★ 2026-10-15 修复（车盖误判，见 §7）**：镜头压低不够时**车自己车盖的上沿**会落进 ROI，那圈暗蓝灰像素
  面积 0.06~0.14、主导度只有 12~18，**压着 0.06 阈值抖** → 两次"没放板就发车"。修法 = `START_GATE_ROI` 底边
  0.95→0.80（A）+ 面积路径**也要主导度≥35**（B，新增 `START_BLUE_AREA_THRESH_BIG=0.20`）+ 画面裁剪
  (`FRAME_CROP_LINE_Y=384`)。当场 30 次武装实测：面积 0.108~0.999、主导度 97~136，**零假报**。

> **★★ 帧率更正（2026-10-15，优先级最高）**：10-12 记的"下摄模组只有 15fps / 瓶颈不在代码或读取方式"
> **是错的**——真凶是 cv2 的 `CAP_PROP_BUFFERSIZE=1` 把驱动砍半（同一设备实测 **14.1 vs 28.0fps**，
> ffmpeg 走同一设备一直是 **29.8**）。`camera_guard.open_camera()` 已修（不设 BUFFERSIZE + 显式 FPS=30）→
> 循迹主循环 **14.7 → 29.9fps**。控制律是"15fps 登记 + 按实测 dt 折算"，**手感不变**（rate.py 的设计点）。
>
> **★★ 增益现场结论（2026-10-15，22 趟真跑；详见 §7）**：亮光下 **`kp 0.10 + kd 0.50 @ 1585`** 最稳
> （`|err|`p90 33、抖动 |Δ舵角|/帧 p90 1.0°、饱和 0%、guard 0），但同参数另一趟触发过 →
> **1590 以上还没证明能持续跑**；**kd ≥0.65 会 D 过载**（抖动 9°+/帧、饱和 7%+ → 画龙保护）。
> 判定三件套（`scripts/diag/lane_ab_summary.py`）：`guard` = 0、抖动 p90 <3°、`|err|`p90 别反弹（反弹=kp 太小）。
> **暗光（AE 长曝光 16.6fps）是独立退化因素**：同参数抖动翻 3~5 倍 → 天黑降速，别在暗光下判高速档。
> 上届参考换算（640px 口径）：等效 kp≈0.10/0.125、kd≈0.19~0.30。
>
> **★ 帧率结论（2026-10-12 定案，取代 10-11 的"锁 15FPS"；上面的更正优先）**：下摄的**真实出帧率随光照变**
> ——亮环境 MJPG 实测 **29.8fps**（跑满），暗环境 AE 拉长曝光（33/60/120ms 台阶）掉到
> **16.7 / 8.3fps**，即 9~30fps 区间；`lane_ref` 检测单帧仅 3.7ms，处理不是瓶颈。
> **因此控制律改成"按实测 dt 折算"，不再锁定某一个帧率**（2026-10-12 落地）：
> 所有增益/窗口的**登记口径 = 15fps**（现场整定时的帧率），运行时按实测 dt 折成连续时间
> 等价形式（`control/rate.py`）：
> · 积分 = ki×15×∫e·dt（**每秒动作不变**；30fps 下逐帧等效 ki 自动减半 0.02→0.01）；
> · 微分 = kd/15×(de/dt)（**等效连续阻尼不变**；30fps 下逐帧等效 kd 自动加倍 0.12→0.24）；
> · 输出平滑按时间常数折算（15fps 的 0.7 ↔ 30fps 的 0.452）、Δe 钳位按 px/s（300px/s）；
> · 滤波窗口/防抖帧数按秒折算（窗口 5 帧@15fps = 10 帧@30fps）。
> **现场 A/B 表继续按 15fps 口径写数字**（0.06 / 0.12 起步 / 0.24），代码自己折算——
> 换帧率不再需要重标 kp/kd。旧结论"ki ×2 要手写在增益里""kd 不折算"已作废。

### 2.6 停车（P1-4）

- **几何先验法（v2.3 定案，不怕裁判怎么放）**：
  1. `parking_area` 标**整个黄色胶布长方形一个框**（不分成两格——分割线可能被板盖住）；
  2. **中间分割线 = 外框水平中点，在 IPM 俯视图里算**（图像中点 ≠ 地面中点，不做 IPM 必判错）；
  3. **蓝板底边中点（接地线）→ IPM → `board_x`**；在俯视图中与中线比：左半被挡 → 停右半格；目标点 = 空闲半格几何中心；
  4. 近距用 HSV 黄线横向对准（ROI 只在 PARKING 状态启用），纵向黄线 y + 里程（**无编码器 → 时间/IMU 推算，精度差一档**）。
- **参考系双保险**：A. 停车区外框（推荐，外框可见时）；B. 赛道左右边界归一化 `ratio=(cx−x_left)/(x_right−x_left)`（外框不可见时兜底；停车区偏一侧时阈值必须现场标定）。**禁止** `cx < 图像宽/2` 判左右（斜进必错）。
- **降级链**：外框+蓝板（主路径）→ 仅一侧外框边（宽度先验补）→ 单框无板（停它）→ 框内有板（取镜像半格）→ 板压中线 ±容差（用底边横向占用范围判，仍不定回溯更远帧）→ 黄胶布完全不可见（低速搜索+超时保守停）。
- **五阶段**：APPROACH（减速接近）→ SLOT_CONFIRM（连续 7 帧投票+置信度+排除不确定区，**锁定后不切换**）→ ALIGN_TO_SLOT（车位中心线，Pure Pursuit/Stanley/带前馈 PID；**不用检测框直接驱动舵机**）→ ENTER_SLOT（低速入库+限舵角变化率）→ FINAL_STOP（黄线+里程联合判断四轮入区）。
- 场地事实（规则初稿插图已核对）：停车区 = 1m（沿行驶方向）×赛道宽，赛道中线黄胶带分两格，**相对行驶方向左右并排**；蓝板挡在**入口边**。选择"早"：3~5m 一次性决策锁定。
- 验收：板在上格停下面 5/5、四轮入区不压线。

### 2.7 IMU（JY901S）

- **驱动**（`hardware/imu.py`）：UART `/dev/ttyS0` B9600、11 字节帧 `0x55 CID 8B SUM` + 校验和、四通道解码（acc/2048、gyro/16、姿态×0.01、**yaw 无符号 0~360**）、读前 tcflush 抢最新；静态零偏标定 100 样（`acc_bias_z=az−1.0`）；静止判据 |g|<2°/s；无硬件自动降级。
- **用法**：直行纠偏（与 servo_center 互补）、S 弯后方向恢复、仲裁"短时维持 0.3~0.8s"、停车对齐；回正闭环（init_yaw±13~20°、P=30、|误差|<1.5° 连续 3 帧、40s 超时）；**IMU 不可用显式降级开环**。
- 10-10 现场：实机验证接线/波特率（yaw 稳定、静止 az≈1.00g）；failed→B9600→115200 对调检查。

### 2.8 ★ 元素集成路线（2026-10-15 定案：一个入口 + 分模块检测器）

**决策**：比赛运行入口 = **`scripts/lane_final_test.py` 一个脚本**（B 路径）；元素检测器保持**独立模块**
（`vision/cone_detect.py` 已有、`vision/elements.py` 已有雏形、`vision/start_gate.py` 已有），由入口 import。
**相位机唯一**（在入口里）负责"谁此刻拥有方向盘"。**A 路径（vision_main + main.py + control/fsm.py）不再并行维护**，
只留作备用/参考（其元素检测器与 FSM 骨架仍可复用；绝不要两边各写一套）。

**相位表（优先级从高到低）**：急停/护栏（跑偏·画龙·丢线超时·看门狗，任何相位都生效）

> 锥桶绕行（位置感知选边）> 循迹（默认）。所有元素抢同一个方向盘 ⇒ 必须由一个相位机仲裁。

**每加一个元素的固定流程（照抄 10-15 成功的路）**：
1. 阈值/时长/幅度全进 `config/settings.py`（`CONE_*` / `ZEBRA_*` 已有底子）；
2. 相位带**开关**（`--cone` / `--zebra` …，**默认关** —— 不写开关时行为必须与"场上验证过的版本"一致）；
3. 单测（合成图 + 假摄像头跑相位机）+ 离线验证（拿一整段空赛道实拍帧量**误检率**，要求零触发）；
4. 现场：轮子架空看读数 → 场地慢速 → 才考虑打开默认。

- **"以前能用后退、后来不能用"的候选原因**（按可能性）：① 电调被误改运行模式（`Fwd/Brake/Rev`→`Fwd/Brake`）
  或上电瞬间油门不在中位导致**行程标定漂移**；② 那次其实是在**官方手动驾驶界面**按的（它有自己的标定）；
  ③ 反向带落在我们没扫过的区间；④ 电池电压低时电调先砍反向。
- **实测工具**：`dev/scripts/diag/esc_probe.py`（台架、四轮**悬空**）：`--plan reverse`（1500→1460/1420/1380/1340/1300，
  档间回中位）/ `neutral`（上扫找起转点=死区）/ `double`（先刹再倒的双踩序列）/ `brake`（1600→1450 vs →1500 对照）。
  默认 dry-run；`--allow-motion` 才写脉宽，脉宽硬钳 [1300,1600]，走 `MotorSession` 安全信封 +
  **独立进程看门狗在位**（被杀/卡死 → 1s 后回中位，而不是停在反向脉宽上）。
- ★★ **2026-10-17 台架实测结论**（`esc_probe.py`，四轮悬空，车端日志
  `/root/dev/logs/esc_probe_20261017_0952*.log`）：
  · **反向：无**。1460/1420/1380/1340/1300us 五档**轮子都没有反向动静**，"双踩"序列（1300 → 回中位
    0.6s → 1300 再给）也不动 ⇒ **这台电调当前配置就是单向前进**（`Fwd` 或 `Fwd/Brake` 模式），
    而且不是"先刹再倒"型；也不是中位漂移造成的（若中位在 1560，1500 附近早该有别的表现，而现场
    多趟验证 1500 = 停）。要反向只能**改电调编程菜单/编程卡**（赛前别动；官方 2026 demo 也是单向）。
  · **前向起转点：1545~1550us**（1545 不动、1550 开始动）⇒ 与登记值 `ESC_DEADBAND_US=1545` 一致
    （差 ≤5us），**中位没漂**；同时说明我们的**蠕速 1560 只比起转点高 ~10us** ——
    ⚠️ 电池弱/低温时起转点会抬升，车可能"蠕不动"（斑马线接近段表现为一直蠕但到不了停车行 →
    12s 上限强制断油、可能停在离横道更远处）⇒ 现场若遇到，`--zebra-creep-us 1565/1570`（或 `--start-us`）。
  · ★★ **"网页端能倒退（有过两次）"已回原码定位**（2026-10-17，`/var/www/orangepi-rc/index.html`
    + `/root/opi-control/`）：官方前端把**电调行程写在页面上**（默认 `min=1400 / center=1500 / max=1600`，
    **每条 drive 消息都带着这三个值**），手柄"扳机模式"油门 = RT − LT（LT = 后退）、"摇杆模式" =
    −(左摇杆 Y)（向下 = 后退）；后端 `percent<0 → 脉宽 = center + (p/100)×(center − min)`
    ⇒ **官方网页的倒车带就是 1400~1500us、最深 1400**（`esc_forward_start_us=1550` /
    `esc_reverse_start_us=1460` 只是**定义了没被调用**的死常量）。
    ⇒ 而我们 `--plan reverse` 已经把 1460/1420 都写过、轮子不动 ⇒ **差别只剩"顺序"**：
    车用电调常见互锁是"**反向只在刚前进过/刹住过之后才放行**"或"**要求油门平滑压过去（跳变只算刹车）**"
    —— 现场那两次能倒，多半就是手柄恰好做对了这个顺序。为此新增 **`--plan fwd-rev`**：
    1600 前进 2s → 1450 停 1.5s → 回中 0.5s（松手窗口）→ 1480→deep 平滑下压（7 档×0.35s、中途不回中位）
    → 压住 2.5s。**先跑这一段，再谈"有没有反向"。**
  · **刹车：悬空判不出来**（轮子惯性太小，1450 与 1500 都"瞬间停"）→ 判定办法二选一：
    ① 手拨轮子：给 1450 时明显发涩/有阻力 = 电调在刹车，给 1500 应很松；② 地面空旷处（人持断电）
    跑一次 `--plan brake`，比较 1600→1450 与 1600→1500 的停车距离。
  · 旁证：这两次跑的看门狗都报了"触发过"（退出码 2）——查它自己的日志（3 条、最后一次 09:53:07
    = 第 2 次探针启动那一秒）确认是**脚本起步空档**（建会话 2.5s + 倒计时 3s 没喂心跳），
    不是跑动中卡死；它写的是 1500 中位、无害。**已修**：看门狗改到"倒计时结束、第一档之前"才拉起。
- **对我们任务的意义**：斑马线 30cm **不依赖刹车**（现在"蠕行→到停车行断油"在低速下滑行可控）；
  若手拨轮子/地面实测有主动刹车 → 30cm 更稳（不必提前很多断油）；**倒车这条路已实测为"不可用"**
  ⇒ 停车入库（P1-4）按**纯前进入库**做（原计划本来如此），别规划倒车纠位。

## 3. 数据与模型（模型轨 = 红绿灯专属 light3cls）

> 其余元素一律不走模型；**类别契约唯一来源** = `dev/config/model_profile.yaml` + `code/classes_smartcar2026.txt` + 本文。

- **模型**：YOLO11n 或 YOLOv5s（按官方 13 号教程链路），3 类 `traffic_light_off/red/green`，imgsz **480×640**（摄像头原生零缩放），conf 0.35（profile `light3cls` 已就绪）；导出 ONNX（opset12/simplify/nms off）→ **RKNN 转换由队友负责**（FP16 优先，INT8+校准可选）。
- **数据现状**：红绿灯 571 张（5 片段，按灯态重标 3 类）；全量盘点 2858 张（7 类，其余类不喂模型）。补拍缺口见 `补拍清单.md`（**灯灭态优先**、远距、负样本≥500、停车位多片段、红锥少量）。
- **采集规范**（红绿灯专项）：**录视频不拍单张**（要"灭→红→绿"完整周期）；矩阵 = 4 距离（5/3/2/1m）× 4 光照（**正午强光必拍**）× 3 横向 × 车状态（行驶+静止）；抽帧：切换瞬间前后 1s 每 0.1s 抽 1 帧（**过渡帧单独归档不得丢弃**），稳定期 0.3~0.5s 抽 1 帧；每类目标 ≥400 实例（1:1:1；**近距离 green 必须够多**——那是真正决策帧）；主力用小车云台摄录（输入分布=部署分布）。
- **标注**：LabelImg，**框整个灯箱**（不是灯珠；灭灯也框得住）；同箱所有帧边界一致；模糊/遮挡帧不标但存 hard_cases；**按片段整组切分 8:1:1**（禁止随机——连续帧泄漏→验证集虚高）。
- **训练**：`code/train_light.sh`（--img 640 --batch 8 --epoch 200 --workers 0，5070 Ti；50 轮基准 conf 0.7~0.9）；标注 1 人 1 天、训练 1 天。
- **验证出口**：单类 AP/conf 分布表；上板 15FPS；与 HSV 互比双通道一致率现场报表。
- 风险：灭灯态标不够 → 灭灯误判绿灯抢跑（+50s）；转 RKNN 的 Linux 机依赖队友。

### 4.4 风险与兜底

| 风险 | 应对 |
|---|---|
| 车停止超 20s = 失败 | 所有等待/停车都有超时兜底；红灯长等口径 P0-4 确认 |

| 5G/网络断连 | 蜂窝优先+WiFi 账本+串口救援（见 `车端网络方案.md`） |

而车上用假摄像头跑真主循环时，**外部信号一律 1 秒内干净停车**（SIGTERM→「收到信号 15」、整组 SIGINT→
「收到信号 2」、SIGHUP→「收到信号 1」）⇒ **不是代码不收，是按键那一下没到进程**。
`sudo` 已排除（车上 `pgtest.sh` 实测：sudo 子进程留在同一进程组）。

**根因（两层）**：
1. **Ctrl+C 只在「该进程就是这个终端的前台作业」时才是信号**（内核把 ^C 交给终端的前台进程组）。
   无 PTY 的通道（`ssh 车 "命令"` / paramiko / AI 工具）、后台 `&`、`nohup`、在别的窗口按 —— **都到不了车**。
   判定口径：`ps -o pid,pgid,tpgid,tty,args -p <pid>`，`tpgid==pgid` 且 tty 非 `?` 才算前台作业。
2. **"以前的蓝板/台架那套能 Ctrl+C 停"不是代码不同，是跑法不同**：那时是**单进程 + 前台 + 在车上的 shell 手敲**
   （`bench_test.py` / `lane_ref_test.py` / `centroid_follow.py`；10-10 现场单当时记的 bug 正是
   "Ctrl+C 不恢复 opi-control" ⇒ 按键真的到了车）。A 路径 `car-mode.sh auto` 则是**同名进程组后台子进程
   + 脚本在前台 `wait` + `trap cleanup EXIT INT TERM HUP` + 自己打印"按 Ctrl+C 结束"**（`car-mode.sh:462-476`）。
   另外两个"看起来能停"的来源：蓝板检测阶段**车本来就不动**（`allowed=False → ControlOut("stop",…,NEUTRAL_US)`）；
   以及**关 SSH/关 5G 的 SIGHUP 会走收尾链停车**（这条在比赛流程里是隐患：要求"关 5G 后继续跑"就得
   脱会话启动，见 §7 该日"下一步"）。

**改法（五件）**：
1. ★ **停止文件通道**（`lane_final_test.py --stop-file`，默认 `/dev/shm/lane_stop`）：**文件存在 = 停车**。
   主循环两处检查点统一走 `stop_requested()`，走与 Ctrl+C **完全相同**的收尾链；**启动清残留、退出也清**；
   `session.json.result.stopped_by` 记 `signal` / `stop-file`。任何通道都能发（第二会话/串口/网页终端/AI 工具），
   不依赖 PTY、不依赖 PID、不依赖命令行特征。
2. ★ **看门狗自保**（`esc_watchdog.py`）：`start_new_session=True`（独立会话）+ **忽略 SIGINT/SIGHUP/SIGQUIT、
   保留 SIGTERM**（主控 `terminate()` 收它）+ **输出重定向到自己的日志**（原来它继承主控那条 `| tee` 管道，
   操作员一断线它下一次 print 就 BrokenPipeError 自杀）+ 循环体"绝不抛"（`_say()`）。
   为什么：主循环卡在 I2C/写盘时，"1 秒后写 1500us"是唯一救命一手，**不能被操作员的按键顺手带走**。
3. **启动自检行**：日志 + `session.json.params.launch` 记录 `tty/pgid/tpgid/keyboard_reaches`
   （`/proc/self/stat` 的 pgrp/tpgid；Windows 上 `os.ttyname` 不存在——本机测试就是这么抓到的，已用 `getattr` 兜）。
4. **收尾链每步 `_try()`**：stdout 可能是断掉的管道（SIGPIPE 已忽略）→ 原来抛在第 1 步会把 `wd.stop()` 与
   `session.json` 落盘全跳过（那两样恰是复盘证据）。
5. **工具/文档**：`stop_run.sh --file`（走文件通道，没人响应再升级 TERM→KILL）+ `--status` 显示停止文件状态；
   `lab_lane_test.sh` 的 GO 提示、`dev/doc/field-lane-ab-20261015.md`、`report.md` §6、AGENTS §1.1/§4.3/§6 同步。

**验收**：本地 24 个测试文件全绿 —— `test_lane_final_run` 12/12（+3 新例：停止文件生效 / 残留不清跑 / 关掉通道）、
`test_esc_watchdog` 5/5（+3 例 **Linux 门控**：抗 INT+HUP 后仍触发 / TERM 仍能收 / 独立会话+自己的日志）、
`test_stop_run` 4/4；**反向验证**：摘掉文件通道 → `test_stop_file_stops_cleanly` 立刻变红（20.0s，max-seconds=20），
还原即绿；`pyflakes` 全仓 86 个 py 文件干净。

① Ctrl+C 杀不动看门狗 ② SIGHUP 同理 ③ TERM 仍能收（`stop_run.sh` 的核验段会报看门狗状态）。
