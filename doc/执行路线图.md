## 0. 目标与"完赛、快"的可操作定义

**总目标**：完赛，并在完赛队伍里尽量靠前。

| 维度 | 可操作定义 |
|---|---|
| **完赛** | 发车 → 巡线 → 斑马线停 10s+播报 → 红绿灯停车等绿灯 → 避 2 锥桶 → 四轮入未遮挡车位 → 扫码付费，**全程无"停车超 20s"、无拖桶 2m、无偏离赛道 10s** |
| **快** | 任务分 = ((Tmax−T有效)/(Tmax−Tmin))²×75 + 5，**平方项** → 每一秒都值钱；但**一次重大失误的代价远大于慢** |
| **靠前的捷径** | ①红绿灯等待**不计入** T有效 → 该等就等；②避免所有罚时项（压线 10s、撞锥 20s、未停够 10s 再 +20s、停车失败 +20s、停错/无轮入区 +100s）；③技术手册 20 分不依赖车速 |

**一句话策略**：**先保证"每项都能过"，再把"每个动作的最优耗时"抠出来**——反过来做（先求快）会在罚时上全吐回去。

## 2. 关键路径与三条并行轨

```text
关键路径（唯一的硬阻塞）：标注 → 切分 → 训练 → 转 RKNN → 上板 → 联调
                          └── 2858 张 + 补拍，2~3 人 1~2 周 ──┘

轨 A 数据/模型（PC 侧，不依赖车）   标注 → 训练 → 转换 → 对拍
轨 B 车端代码（本地 mock + 车）     发车修复 → 扫线/PID → 减速停准 → FSM → 停车
轨 C 现场标定（必须上车/到场）       几何实测 → 阈值标定 → 分档俯仰 → 全链路整定
```

**排期原则**：轨 A 是长尾，**必须最先启动**；轨 B/C 要在轨 A 出模型之前就绪，否则模型到了也没处用。

## 8. 风险与兜底

| 风险 | 应对 |
|---|---|
| **标注拖尾**（唯一关键路径，2~3 人 1~2 周） | 先标难类（红绿灯/停车）；多数类按 `--stride` 抽帧降冗余；宁可少而精，不要海量重复帧 |
| 红绿灯识别不稳（倒计时随机 3~10s） | 视频采"灭→红→绿"全过程；`off` 必标；连续 5 帧 + 置信度；HSV 分区二次校验；**超时兜底** |
| **光敏传感器不满足 1m** | 必须更换（E18-D80NK）；阈值现场可调；状态机加超时**防死锁** |
| 红绿灯在 40cm 高、近距离下摄看不到 | 云台摄 + 预设俯仰分档；双摄分时复用；等待时车辆静止可低频多帧累积 |
| **连续帧泄漏 → 验证集虚高** | 严禁按图片随机划分；按片段整组切分；Roboflow 里不做划分 |
| 停车类数据片段少、泛化差 | 补拍 400~500 张、多片段多光照；蓝板多种放法 |
| 两个模型抢 NPU | 分频运行（检测 15~30 FPS、分割 5~10 FPS）；先用"单一推理线程 + 任务队列"（简单），必要时再上 core mask 隔离 |
| 锥桶随机位置撞桶（+20s，拖 2m = 失败） | 近端避障优先保"不撞"，宁可慢；绕行留足横向余量 |
| **停不准**（不足四轮入区 +20s / 停错 +100s） | P1-2 的减速停准是前提；IPM + 几何先验远距决策、近距 HSV 精调；四轮入区连续 3 次验证 |
| 压线/骑线（+10s，持续 3s +50s） | 巡线留中线余量，不要贴边跑；弯道主动降速 |
| 手机热点不稳/比赛违规 | 比赛用手车 4G/5G 模块（局域网罚 200s，自主阶段遥控罚 300s） |
| 供电不可改造（螺丝不可拆） | 软件降载：关无关服务、推理帧率分级、监测温度与意外重启日志 |
| 官方图传服务器比赛当天拥塞 | 8080 通道冗余 + 自建 mediamtx 兜底（ADR 待办） |
| 正式规则与初稿有差异 | 保留 2025 的变道代码路径可快速恢复；规则发布后立刻复核几何与罚则 |
| **程序异常退出导致车继续跑** | 所有退出路径统一 `cleanup()`：电调归零、舵机回中、释放 PCA9685/摄像头、恢复推流（`AGENTS.md` §1.1） |

## 9. 模拟赛检查单（每次跑完打勾）

- [ ] 发车：挡板移除后才动，无"上电即冲"
- [ ] 斑马线：停在距横道边缘 30cm 内，停够 10s，播报内容与学校/队名一致
