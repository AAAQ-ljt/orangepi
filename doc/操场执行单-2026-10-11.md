> 不能闭环的拿到判据数字。比 10-10 版执行单的全流程加强版（10-10 版未执行则直接并入本单）。

## 1. 到场基线（≈30 分钟）

1.1 场地观察 2 分钟：赛道底色/光照/实际宽度目测，与实验室差异记录
1.2 `bash car-mode.sh status`：手动模式服务全 active；`car-mode.sh stream up` 后浏览器看图传确认两路画面
1.3 **发车 5/5 复验**（B 路径 lane_ref_test --no-motor）：板在=停 / 移开=走 / 放回=停，连做 5 次
1.4 **直行基准 + 转向符号**：`bench_test.py --steer-test --allow-motion`（舵机 90→110→70 时前轮先左后右 = steer_sign -1 正确）；直行基准=90° 时的实际走向，偏差 >10cm/5m 则记 servo_center_angle 修正值（**改 site.yaml 前先记录现值**）
1.5 **视角体检**：`lane_probe --camera 2 --frames 6`——白线在不在画面下半部、ROI 罩不罩得住；体检结论记入对比表（决定 §3.1 的 4 方案 ROI 适配）

## 2. 感知层：元素判据摆位（探针，≈2 小时，车不动）

| # | 元素 | 摆位矩阵 | 记录项 | 判定标准 |
|---|---|---|---|---|
| 2.1 | **斑马线** | 白纸斑马线 1m / 2m / 3m / 5m 各 1 次 | 连通域数、面积、形状闸门开关两档 | 官方参数（180/200/≥4）在几米断开；闸门开是否误杀；记录现场该用哪档 → 回填 settings |
| 2.2 | **红绿灯 HSV** | 灯（或 LED 模拟器）1/2/3/5m × 灭/红/绿三态 | 互比读数（红占比/绿占比）、分区两读数（左 1/3、右 1/3） | 哪距离断检、强光下是否失效；三态是否可区分 |

## 3. 行为层：车体闭环（≈2.5 小时，场地空旷，有人拿急停）

### 3.1 循迹 4 方案选型（本场核心决策）

| 方案 | 入口 | 参数 | 测法 |
|---|---|---|---|
| ④ 边缘法 ★唯一可用 | `lane_ref_test.py`（参考实现版） | 自检自动选带/目标点；**加 `--single-hold` A/B**；试 `--kd 0.2 --smooth 0.8` | 直道 10m ×2 + S 弯 ×2 |
| ~~③ 双线质心~~ | ~~centroid_follow --scheme 3~~ | ~~KP7/KD3/阈值190~~ | **已淘汰（10-10 实测反光拉偏质心，max 误差 358px）** |
| ~~② 单线质心~~ | ~~centroid_follow --scheme 2~~ | ~~KP0.6/KD0.1/阈值185~~ | **已淘汰（同上）** |

**10-10 首轮复盘要点（9 组数据）**：检测器本身优秀（双侧 184/273、误差中位 −6px）；败因 = 左线频繁丢 → 单侧兜底中心跳（可见线读数飘）→ 蛇形 → 一提速（1575+）就触发护栏。
**速度目标（2026-10-11 用户定案）**：巡航 **1580**（默认已是 1580，调试上限内），1560 龟速不可接受。
  提速前提 = 增益帧率折算（kd 0.24）+ `--single-hold` 已上车（此前 1575/1585 全灭是未修复前的旧账）。
  现场验证顺序：直道先 `--speed-us 1580 --single-hold` 试跑 → 蛇形则 `--kd 0.3 --smooth 0.8` →
  再不稳降到 1570 找台阶；**不允许回到 1560**。丢线瞬间 single-hold 短暂降速属正常安全行为，
  双侧恢复自动回 1580。

每遍记录：**压线次数 / 丢线停车次数 / 中心跳动（max 跳变 px）/ 是否画龙**；S 弯冲出 1 次即记 ❌。
现场按"不压线 > 不丢线 > 中心稳"排序，**选中 1 个**作为后续 3.2/§4 的主线（未选中的至少在直道复测 1 次确认是方案问题还是视角问题）。
ROI 适配：先用 `ref_roi_probe --sweep` 看现场线带，4 方案 ROI 都按实测线带适配后再比（借方法不借数字）。

### 3.2 锥桶行为（B 路径已闭环，接着 3.1 选中的入口）

1. `--cone-stop` 实验室模式：蓝锥放**下摄 ROI 内**（画面中下部）→ 车检出停车（终端 `锥桶 N 个` 打印）→ 移开自动继续；
   无锥桶时完全不报（负例验证 ×1）；
2. 确认检出稳定后 `--cone-avoid`：S 型绕行 2 遍，记录是否碰锥/绕行时间；
3. 若检出不稳：现场调 HSV（2.4 结果）重测，不再依赖模型通道（4cls 已退役）。

### 3.3 IMU 实机（`hardware/imu.py` 首次上实车）

1. 静止 10s：yaw 稳定（±1° 内）、az≈1.00g；2. 手动转车 90°：yaw 跟随方向正确（顺/逆时针符号）；
3. 波特率检查：读数乱/无输出 → B9600 与 115200 对调（记录车端实际波特率）；
4. 结论回填：IMU 是否可作直行纠偏与开环降级（不可用则退化为纯 servo_center，不阻塞）。

### 3.4 相机提速对比

同一视角分别跑 `--fourcc MJPG` 与默认 YUYV，各数 10s 帧数（FPS 对比表）；MJPG 显著更高 → 记入默认参数建议。

## 4. 链路层：A 路径串联（≈1 小时）

- 4.1 `car-mode.sh auto --dry-run`：确认 视觉进程出帧 → UDP → 控制端 FSM `WAIT_START→TRACKING` → 状态文件更新；
      全程**不使能电机**（这就是 dry-run 的意义），观察协议字段（center_x/conf/lane_n）流转；
- 4.2 **若 §0 接线前置已完成**：放板发车 → 斑马线触发 ZEBRA_STOP（停 10s 计数）→（若现场有灯）TRAFFIC_LIGHT 等待 →
      锥桶 AVOID_CONE → 停车 PARKING 触发，逐状态看 `[FSM]` 打印；**未接线则本项记"待接线"**，用 §3.2 的 B 路径行为作替代证据；
- 4.3 UDP 契约抽查：对照 `common/protocol.py` 字段表，确认视觉发的内容与契约一致（新增 lane_n_left/right、元素字段占位）。

## 7. 风险与优先级预案

| 风险 | 预案 |
|---|---|
| 场地不可用/下雨 | 实验室台架替代：台架把 2.2/2.4 用合成灯/LED 模拟先跑；3.1 只留本地 4 方案读数表 |
| 视角体检全败（线不进画面） | 不依赖白线：固定舵角 + 元素触发完成赛任务（记录 serv_center 修正值）；循迹选型改为数据记录 |
| 时间不够 | 砍序：先 5（几何+补拍，数据最刚需）→ 2（感知判据）→ 3.1（选型）→ 3.2/3.3/3.4 → 4（链路，接线未完成时可省略） |
| 退出保护异常（opi-control 没恢复） | 手工 `systemctl start opi-control ffmpeg-stream ffmpeg-stream-sub` + 复验；记录到收尾清单 |
| 电池/推流掉线 | 换电后 `stream up` 复验；图传黑屏先查 mediamtx publisher（见 `车端网络方案.md`） |
