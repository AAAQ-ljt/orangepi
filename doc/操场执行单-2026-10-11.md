### 3.2 锥桶行为（B 路径已闭环，接着 3.1 选中的入口）

1. `--cone-stop` 实验室模式：蓝锥放**下摄 ROI 内**（画面中下部）→ 车检出停车（终端 `锥桶 N 个` 打印）→ 移开自动继续；
   无锥桶时完全不报（负例验证 ×1）；
2. 确认检出稳定后 `--cone-avoid`：S 型绕行 2 遍，记录是否碰锥/绕行时间；
3. **★ 三位置矩阵（任务 A，10-11 新增）**：锥桶分别摆 居中 / 偏左 / 偏右 各一遍，
   记录终端"检测到锥桶（偏左/偏右/居中）"选侧是否正确（偏左→右绕、偏右→左绕、
   居中→默认 left）、是否碰锥、绕行耗时；容差 `CONE_SIDE_TOLERANCE_PX=60`（settings）；
   **边界组（cones[0] 判据盲区，Task B 输入）**：近锥居中 + 远锥偏侧 各一遍——
   记录终端选侧（预期日志判"居中"走默认 left）与实际是否碰锥；说明：两锥同时可见时
   选侧取**最近锥**（cones[0]，面积最大）的位置，不是锥对中点（那是 Task B 的 choose_gap 判据）。
4. 若检出不稳：现场调 HSV（2.4 结果）重测，不再依赖模型通道（4cls 已退役）。

### 3.3 IMU 实机（`hardware/imu.py` 首次上实车）

1. 静止 10s：yaw 稳定（±1° 内）、az≈1.00g；2. 手动转车 90°：yaw 跟随方向正确（顺/逆时针符号）；
3. 波特率检查：读数乱/无输出 → B9600 与 115200 对调（记录车端实际波特率）；
4. 结论回填：IMU 是否可作直行纠偏与开环降级（不可用则退化为纯 servo_center，不阻塞）。

### 3.4 相机提速对比

用 `diag/measure_fps.py`（10-11 新增的帧率/耗时诊断脚本，自动测 YUYV/MJPG/分辨率档 + 检测耗时）：
`sudo python3 /root/dev/scripts/diag/measure_fps.py`（先停推流或让脚本提示）。10-11 已实测：
640/320 × YUYV/MJPG 全部 15.0FPS（模组硬限制）——本场仅在更换摄像头/接线后才需复测。

## 4. 链路层：A 路径串联（≈1 小时）

- 4.1 `car-mode.sh auto --dry-run`：确认 视觉进程出帧 → UDP → 控制端 FSM `WAIT_START→TRACKING` → 状态文件更新；
      全程**不使能电机**（这就是 dry-run 的意义），观察协议字段（center_x/conf/lane_n）流转；
- 4.2 **若 §0 接线前置已完成**：放板发车 → 斑马线触发 ZEBRA_STOP（停 10s 计数）→（若现场有灯）TRAFFIC_LIGHT 等待 →
      锥桶 AVOID_CONE → 停车 PARKING 触发，逐状态看 `[FSM]` 打印；**未接线则本项记"待接线"**，用 §3.2 的 B 路径行为作替代证据；
- 4.3 UDP 契约抽查：对照 `common/protocol.py` 字段表，确认视觉发的内容与契约一致（新增 lane_n_left/right、元素字段占位）。
