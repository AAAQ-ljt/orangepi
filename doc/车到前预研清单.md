# 车到前预研清单(2026 智能车)

> 原则:**所有不需要实车的工作,全部在 PC 上提前完成**。车到货→比赛时间紧,能提前的不留到后面。
> 使用方法:每完成一项打勾并填「负责人 + 日期」。配套文件:《资料学习导读.md》。
> 目标(到货前的完成定义):PC 上能演示 ①录播视频→感知管线→PerceptionFrame 正确输出;②FSM 在模拟事件下跑完 BOOT→DONE 全状态;③RKNN 模型在 PC 模拟器上推理正确。

---

## A. 环境与仓库(约 1 天)

- [ ] 建立 Git 仓库(私有即可),main 分支保护 + 提交规范(参考设计文档 §8)
- [ ] PC 安装 Python 3.11 + venv,安装:ultralytics、opencv-python、numpy、pydantic、pytest、ruff、mypy
- [ ] 按设计文档 §5 创建 `2026-orange-pi\` 骨架仓库目录
- [ ] 查清 rknn-toolkit2 要求的 Python 版本(通常需独立 venv,勿与 ultralytics 环境混用)

## B. 模型链路验证(约 2~3 天,可与 C 并行)

- [ ] 用 `best11nseg.pt` 在 PC 上跑通推理(单图/视频),确认 12 类输出正常
- [ ] 导出 ONNX,记录输入/输出节点名称与形状
- [ ] rknn-toolkit2 转 RKNN(FP16),在 **PC 模拟器**上跑通,对比转换前后精度(样例图 + 关键类别)
- [ ] 若 YOLO11-seg 导出 RKNN 踩坑 → 启动 fallback 评估:detect 版 + OpenCV 车道中线(设计文档 §9)
- [ ] 把转换命令、坑、验证结果写进 `docs\rknn-notes.md`

## C. 骨架代码(约 2~3 天)

- [ ] `hardware\` 接口定义(Protocol)+ Mock 实现(设计文档 §4.1)
- [ ] `PerceptionFrame` / `ControlCommand` 数据类(设计文档 §3.2)
- [ ] FSM 表驱动解释器 + `config\fsm.yaml` 样例 + 全状态转移单测(设计文档 §4.3)
- [ ] PID 控制器纯函数实现 + 单测
- [ ] 录播/回放框架:录制 manifest 格式定义 + 回放 CLI(设计文档 §4.5)
- [ ] **全链路假数据演练**:一段假 PerceptionFrame 流 → FSM → 控制量 → Mock 硬件输出

## D. 遥测与工具(约 1 天,选做)

- [ ] FastAPI 仪表盘骨架(可后置到有车之后)
