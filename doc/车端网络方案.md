# 车端网络方案（蜂窝优先 · WiFi 账本兜底 · 服务器可切换）

> 建立于 2026-09-16。对应的实现全部在 `dev/scripts/net/`。
> 目标：**让小车的联网足够健壮**——上电自己连、只占一条上行、换卡能用、换服务器只改一处、关机优雅断开。

---

## 0. 一页速览

| 项 | 做法 |
|---|---|
| 上电联网 | `car-net.service`（开机 oneshot）→ `car-net.sh auto`：**先流量卡，没有再 WiFi** |
| 只占一条上行 | 任一路连上后，自动把另一路的 `autoconnect` 关掉；蜂窝路由 metric 100 < WiFi 600 |
| 换卡能用 | APN 按列表轮询（**实测本车联通卡：3gnet 可通、cmnet 会 CID 超时**） |
| WiFi 配置 | `wifi-ledger.conf` 账本（`SSID|密码|优先级`），用户直接编辑，`wifi sync` 生效 |
| 优雅断开 | `car-net.sh cellular down` 会停会话 + 释放 CID + 清地址路由；关机由 `car-net-down.service` 自动执行 |
| 换服务器 | 只改 `car-net.conf` 里的 `MEDIA_RTSP` / `FRP_*`，然后 `car-net.sh apply` |
| 断网救援 | 串口：`python scripts/serial_car.py "命令"` / `python scripts/serial_push.py 本地 远端` |

## 1. 分层结构（谁负责什么）

```text
/root/dev/scripts/net/
├── car-net.conf          ← 【唯一配置入口】策略 + APN 列表 + 服务器端点
├── wifi-ledger.conf      ← 【用户可编辑】WiFi 账本：SSID|密码|优先级
├── car-net.sh            ← 网络总管（status/auto/cellular/wifi/apply/policy/tunnel）
├── car-net.service       ← 开机执行 auto（enabled）
└── car-net-down.service  ← 关机/重启时优雅断开蜂窝（enabled）

/etc/systemd/system/car-net*.service   ← 上面两个单元的安装位置（由 apply 或手动 cp）
/etc/default/smartcar-media            ← 由 car-net.sh apply 生成（图传地址）
/root/frp/frpc-ssh.ini                 ← 由 car-net.sh apply 生成（隧道配置）
```

**变更影响的传播链**（改一处 → 一条命令 → 全部生效）：

```text
car-net.conf ──apply──▶ /etc/default/smartcar-media ──restart──▶ ffmpeg-stream(-sub)
             └────────▶ /root/frp/frpc-ssh.ini       ──restart──▶ frpc-ssh（SSH/网页/域名）
```

## 2. 上电流程（car-net.sh auto）

```text
① 蜂窝优先（PREFER_CELLULAR=yes）
   等最多 CELL_TIMEOUT 秒，看 wwan0 是否已有地址且能出网
     ├ 有 → 采用它（可能由官方 simcom-cm 或上次会话提供）
     └ 没有 → cellular_up：
          ├ APN 轮询（3gnet → cmnet → ctnet → …，第一个出网的胜出）
          └ 都不行 → 厂商 simcom-cm 兜底（VENDOR_DIAL_FALLBACK=yes）
② 蜂窝确认可用 → apply_policy：关掉 WiFi 的 autoconnect（只占一条上行）
③ 蜂窝不可用且 WIFI_FALLBACK=yes → wifi sync + wifi up（按账本优先级挑当前能搜到的热点）
④ 每步都写 /root/dev/logs/car-net.log
```

诊断命令：

```bash
bash /root/dev/scripts/net/car-net.sh status          # 一眼看清：出口/蜂窝/WiFi/隧道/图传
bash /root/dev/scripts/net/car-net.sh cellular status
bash /root/dev/scripts/net/car-net.sh wifi list        # 账本 + 当前可见热点
tail -f /root/dev/logs/car-net.log
```

## 3. WiFi 账本怎么用（用户视角）

```bash
# ① 把车上已有的 WiFi 导出成账本（含真实密码，推荐先做这一步）
sudo bash /root/dev/scripts/net/car-net.sh wifi export

# ② 直接编辑账本，一行一个热点：SSID|密码|优先级（数字小优先）
sudo nano /root/dev/scripts/net/wifi-ledger.conf

# ③ 同步成 NetworkManager 连接（幂等，可反复执行）
sudo bash /root/dev/scripts/net/car-net.sh wifi sync

# ④ 手动连一下试试 / 断开
sudo bash /root/dev/scripts/net/car-net.sh wifi up
sudo bash /root/dev/scripts/net/car-net.sh wifi down
```

说明：
- 密码留空的条目会被**跳过**（除非系统里已有同名配置），避免写错密码把能用的连接搞坏；
- `wifi sync` 只创建/更新，不删除其他连接；
- 账本同步出来的连接默认 `autoconnect=no`，由 `auto`/`policy` 决定何时启用，
  这样就不会出现"蜂窝和 WiFi 抢路由"。

## 4. 换服务器 / 换热点（可解耦的关键）

```bash
sudo nano /root/dev/scripts/net/car-net.conf      # 改 MEDIA_RTSP 与 FRP_* 几行
sudo bash /root/dev/scripts/net/car-net.sh apply  # 渲染系统配置并重启相关服务
```

`apply` 会：写 `/etc/default/smartcar-media`、写 `/root/frp/frpc-ssh.ini`、
重启 `frpc-ssh` 与两个推流服务，并在 `car-net.log` 留痕。

> 好处：换服务器/换端口不需要动脚本、不需要记 4 个文件的位置，
> 也不会再出现"改了推流地址忘了改隧道"这种半切换状态。

## 5. 优雅断开与硬复位（为什么重要）

现象复盘（2026-09-16）：

- 团队的 `car-dial.service` 反复报 `CID allocation failed in the CTL client: endpoint hangup`——
  根因是**上一次会话的 CID 没有释放**（断电/强杀导致），下一次拨号拿不到 CID，于是无限重试；
- 厂商 `simcom-cm` 也会卡住：它是个**闭源二进制**（`1e0e:9001 SIMCom 5G`），
  不打印日志、内部维持着旧的 QMI 会话，被抢过设备之后就再也拨不上去。

**现在的三层兜底**（`cellular up` 依次尝试，任一成功即返回）：

```text
① APN 轮询（3gnet → cmnet → ctnet → …）        ← 首选：快、换卡即用、不依赖厂商二进制
② 厂商 simcom-cm 兜底                          ← 对它验证过，但可能卡在旧会话
③ USB 硬复位模组 + 重试 ①②                     ← 最后手段，等价"重新插拔模组"
```

③ 的实现（**实测有效**）：

```bash
echo 2-1 > /sys/bus/usb/drivers/usb/unbind   # 2-1 = 模组 USB 设备（按 idVendor 1e0e 自动探测）
sleep 4
echo 2-1 > /sys/bus/usb/drivers/bind         # 重新枚举 → /dev/cdc-wdm0 与 wwan0 自动回来
# 然后重新设置 raw_ip=Y、link up、再走 ①②
```

手动使用：`car-net.sh cellular reset`（只复位）/ `car-net.sh cellular recover`（复位并重拨）。

**优雅断开**（`car-net.sh cellular down`）：

```bash
qmicli --wds-stop-network=<CID>        # 停数据会话
qmicli --wds-release-client-id=<CID>   # 释放 CID（关键：不留僵尸 CID）
ip addr flush wwan0 / 删默认路由 / resolvectl revert
```

`car-net-down.service` 把它挂在关机路径上（`ExecStop=... cellular down`），
所以正常关机/重启都会先优雅释放，下一次上电就能干净地重新拨号。

> `car-dial.service`（跑 `/root/car_net_up.sh` 的旧服务）已 `disable`，职责被 `car-net.service` 取代；
> 厂商 `simcom-cm`（`/etc/rc.local` 启动）保留为兜底②。

## 5.1 WiFi 的两个坑（2026-09-16 实测）

1. **手机热点 DHCP 偶发不给地址**：NM 日志报
   `state change: ip-config -> failed (reason 'ip-config-unavailable')`——
   密码、关联都正常，只是没拿到租约（热点客户端数满/设备白名单/瞬时限流）。
   → 已加**3 次重试**；仍不行可给账本加第 4 列写静态地址：
   `Aaaq|密码|10|10.129.7.50/24,10.129.7.169`（格式 `IP/前缀,网关`）
2. **别用 NM 的 `connected` 状态判断"网络可用"**：DHCP 拿到地址后 NM 还会做连通性检查，
   会**停在 `ip-check` 十几秒**，期间 `nmcli dev status` 显示的不是 connected。
   早期版本因此把已经连上的 WiFi 主动断开了。现在判定标准是
   **"接口上有 IPv4 地址"**（`connected`/`ip-check`/`ip-config` 均算成功）。

**两条链路共存但不互抢**：蜂窝由脚本加 `metric 100 onlink` 的默认路由，
WiFi 由 NM 加 `metric 600` 的默认路由 → 蜂窝优先，WiFi 自动成为备份，
不需要人为切换（策略层只负责关掉"另一条"的 autoconnect，避免开机时两条一起抢）。

## 6. 串口救援（网络全断时）

小车的调试串口：**CH340 → COM8 / 1500000 / 8N1**。

```bash
# 执行命令（自动登录，命令标记捕获，不受网络影响）
python scripts/serial_car.py "ip -4 a show wwan0; ip r"
python scripts/serial_car.py --timeout 180 "sudo bash /root/dev/scripts/net/car-net.sh auto"
python scripts/serial_car.py --raw                 # 只看串口输出（看启动日志）

# 推文件上车（分块 base64 + sha256 校验，网络断了也能部署）
python scripts/serial_push.py dev/scripts/net/car-net.sh /root/dev/scripts/net/car-net.sh --mode 755
```

> ⚠️ 串口终端一次只能被一个程序占用：用本工具前请先关掉你的串口终端。
> ⚠️ 传绝对远端路径时加 `MSYS_NO_PATHCONV=1`（Git Bash 会把 `/root/x` 转成 Windows 路径；
> `serial_push.py` 已内置自动纠正）。

## 7. 故障排查

| 现象 | 处理 |
|---|---|
| 蜂窝没 IP | `car-net.sh cellular up`；看日志里每个 APN 的失败原因；确认卡没欠费、天线接好 |
| 有 IP 但不出网 | 看默认路由是不是 wwan0（`ip r`）；`car-net.sh policy` 修路由优先级 |
| 拨号报 CID allocation failed | 上一次会话没释放 → `car-net.sh cellular down` 再 `up`（现在关机也会自动释放） |
| WiFi 连不上 | `car-net.sh wifi list` 看账本条目是否在可见列表里；确认密码；`wifi sync` 后 `wifi up` |
| 两条链路抢路由 | `car-net.sh policy`（会按"蜂窝优先"重新分配 autoconnect） |
| 隧道断 | `systemctl status frpc-ssh`；`car-net.sh tunnel` 重启；确认服务器地址/token（`car-net.sh apply`） |
| 图传推不上去 | `systemctl status ffmpeg-stream`；确认 `MEDIA_RTSP` 与服务器 8554 可达 |
