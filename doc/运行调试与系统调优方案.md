# 运行调试与系统调优方案

> 本文档定义小车运行时的双进程架构、调试方式和系统性能调优策略。

---

## 一、运行架构

保持两个进程：

```text
vision 进程：摄像头 → 预处理 → RKNN NPU → 后处理 → UDP + 状态文件
control 进程：UDP → FSM → Planner → Driver
```

### 通信

- 主链路：**UDP**（127.0.0.1:5000）；
- 辅助调试：**共享状态文件** `/tmp/smartcar_status.json`；
  - vision 进程定时写入当前 FPS、检测结果、center_x 等；
  - 便于你在 X11/日志中一眼看到状态。

### 线程池

视觉进程内部使用线程池/流水线：

```text
线程A：采集 + 预处理
线程B：NPU 推理
线程C：后处理 + UDP 发送
```

目标：让 NPU 推理和 CPU 后处理重叠，提升 FPS。

---

## 二、调试方式

调试窗口有**两个独立入口**（`dev/vision/vision_main.py` 本身**没有** `--debug` 参数，旧文档里那种写法会报错）：

| 入口 | 用途 | 命令 |
|---|---|---|
| `dev/vision/debug_view.py` | 可视化调试：实时画面 + 检测框 + FPS + 推理耗时 + 识别状态 | `PYTHONPATH=/root/dev python3 vision/debug_view.py --model /root/dev/models/xxx.rknn` |
| `dev/vision/vision_main.py` | 正式运行：无窗口，每帧打印 fps/各段耗时/关键状态 | `PYTHONPATH=/root/dev python3 vision/vision_main.py --model /root/dev/models/xxx.rknn --udp-ip 127.0.0.1` |

调试窗口显示：

- 摄像头实时画面；
- FPS；
- 推理耗时；
- 检测框；
- 关键状态：`center` / `zebra` / `cone` / `A` / `B` / `L` / `R`。

> 两者都会**先停 ffmpeg 推流、退出时自动恢复**，`q` 或 `ESC` 退出。
> ⚠️ 本车**没有 X 服务器**（`x11.sh` 这个名字在车上并不存在），窗口程序（`debug_view.py`、探针的 `--show`）
> 默认跑不起来；调参/看画面走 `dev/scripts/diag/lane_probe.py`（终端结论 + 叠加图）或浏览器图传（见 `AGENTS.md` §4.3）。
> ⚠️ `vision_main.py` 目前每帧打印一行状态（含 5 个数字），15~25 FPS 下日志本身会吃掉可观 CPU，正式跑车前应改为**降频打印**（如每 10 帧一次）或写 `smartcar_status.json`。

## 三、系统性能调优

### 原则

**只有在小车运行代码时才开启 performance，运行结束必须恢复。**

### 开启脚本（示例）

```bash
#!/usr/bin/env bash
# enable_performance.sh
echo performance > /sys/class/devfreq/dmc/governor
echo performance > /sys/class/devfreq/fb000000.gpu/governor
echo performance > /sys/class/devfreq/fdab0000.npu/governor
for i in 0 4 6; do
  echo performance > /sys/devices/system/cpu/cpufreq/policy$i/scaling_governor
done
```

### 恢复脚本

```bash
#!/usr/bin/env bash
# restore_performance.sh
echo ondemand > /sys/class/devfreq/dmc/governor
echo ondemand > /sys/class/devfreq/fb000000.gpu/governor
echo ondemand > /sys/class/devfreq/fdab0000.npu/governor
for i in 0 4 6; do
  echo ondemand > /sys/devices/system/cpu/cpufreq/policy$i/scaling_governor
done
```

> 注意：不同板子路径可能略有不同，先确认路径存在再执行。

## 四、安全要求

- 系统调优前确认小车处于安全状态；
- 运行结束后必须恢复 governor；
- 温度过高时禁止强制 performance；
- 所有 real 测试必须轮子架空或空旷场地。
---

## 五、已提供的安全/模式切换脚本

以下脚本位于小车 `/root/dev/scripts/`：

| 脚本 | 作用 |
|---|---|
| `safe_pwm_init.sh` | 启动 opi-control，确保 PCA9685 安全初始化 |
| `run_capture.sh` | 拍照前停推流，结束后恢复 |
| `run_video.sh` | 录像前停推流，结束后恢复 |
| `run_hardware_test.sh` | 硬件测试前停 opi-control，结束后恢复 |
| `start_autonomous.sh` | 进入自动驾驶：关闭手动服务，启动 vision + control |
| `stop_autonomous.sh` | 退出自动驾驶，恢复手动服务 |

### 使用方式

```bash
# 上电后确认安全
bash /root/dev/scripts/safe_pwm_init.sh

# 拍照
bash /root/dev/scripts/run_capture.sh --folder lane

# 录像
bash /root/dev/scripts/run_video.sh --folder lane

# 硬件测试
bash /root/dev/scripts/run_hardware_test.sh ./your_test

# 自动驾驶
bash /root/dev/scripts/start_autonomous.sh

# 退出自动驾驶恢复手动
bash /root/dev/scripts/stop_autonomous.sh
```

## 六、摄像头拍照/录像脚本

`dev/img/` 下提供两个摄像头包装脚本：

| 脚本 | 对应摄像头 | 关闭的服务 |
|---|---|---|
| `camera0.sh` | /dev/video0 | ffmpeg-stream.service |
| `camera2.sh` | /dev/video2 | ffmpeg-stream-sub.service |

用法：

```bash
# 拍照
bash /root/dev/img/camera0.sh photo --folder lane
bash /root/dev/img/camera2.sh photo --folder cone

# 录像
bash /root/dev/img/camera0.sh video --folder lane
bash /root/dev/img/camera2.sh video --folder cone
```

脚本退出后会自动恢复对应推流服务。
