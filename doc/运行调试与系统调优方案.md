# 运行调试与系统调优方案

> 本文档定义小车运行时的双进程架构、调试方式和系统性能调优策略。

---

## 一、运行架构

保持两个进程：

```text
vision 进程：摄像头 → 预处理 → RKNN NPU → 后处理 → UDP + 状态文件
control 进程：UDP → FSM → Planner → Driver
```

### 通信

- 主链路：**UDP**（127.0.0.1:5000）；
- 辅助调试：**共享状态文件** `/tmp/smartcar_status.json`；
  - vision 进程定时写入当前 FPS、检测结果、center_x 等；
  - 便于你在 X11/日志中一眼看到状态。

### 线程池

视觉进程内部使用线程池/流水线：

```text
线程A：采集 + 预处理
线程B：NPU 推理
线程C：后处理 + UDP 发送
```

目标：让 NPU 推理和 CPU 后处理重叠，提升 FPS。

## 二、调试方式

调试窗口直接集成进 `vision_main.py`：

```bash
PYTHONPATH=/root/dev python3 vision/vision_main.py --debug --model /root/dev/models/best_int8.rknn
```

窗口显示：

- 摄像头实时画面；
- FPS；
- 推理耗时；
- 检测框；
- 关键状态：
  - TRACK: YES/NO
  - A/B/LEFT/RIGHT/ZEBRA/CONE/BARRIER: YES/NO
  - CENTER_X

## 三、系统性能调优

### 原则

**只有在小车运行代码时才开启 performance，运行结束必须恢复。**

### 开启脚本（示例）

```bash
#!/usr/bin/env bash
# enable_performance.sh
echo performance > /sys/class/devfreq/dmc/governor
echo performance > /sys/class/devfreq/fb000000.gpu/governor
echo performance > /sys/class/devfreq/fdab0000.npu/governor
for i in 0 4 6; do
  echo performance > /sys/devices/system/cpu/cpufreq/policy$i/scaling_governor
done
```

### 恢复脚本

```bash
#!/usr/bin/env bash
# restore_performance.sh
echo ondemand > /sys/class/devfreq/dmc/governor
echo ondemand > /sys/class/devfreq/fb000000.gpu/governor
echo ondemand > /sys/class/devfreq/fdab0000.npu/governor
for i in 0 4 6; do
  echo ondemand > /sys/devices/system/cpu/cpufreq/policy$i/scaling_governor
done
```

> 注意：不同板子路径可能略有不同，先确认路径存在再执行。

---

## 四、安全要求

- 系统调优前确认小车处于安全状态；
- 运行结束后必须恢复 governor；
- 温度过高时禁止强制 performance；
- 所有 real 测试必须轮子架空或空旷场地。
