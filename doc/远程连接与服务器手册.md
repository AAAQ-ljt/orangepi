## 2. 两种连接方式

### 2.1 方式一：隧道（主链路）

```text
[小车] --WiFi(热点/5G)--▶ frpc ──▶ 121.40.149.155:7000 (frps) ──2222──▶ 任意机器
```

- 链路组成：小车 `frpc-ssh`（systemd 开机自启、断线重连）→ 服务器 `frps`
- 服务器上 2222 反代到小车 22；8080 反代到小车 80（nginx 网页控制）

### 2.2 方式二：热点直连（备用）

```text
[小车 10.68.1.43] —— 手机热点 —— [本机 Windows]
```

- 热点 DHCP 分配 IP **可能变化**：连不上先让用户确认小车当前 IP（车上 `hostname -I`，或热点后台看设备列表）
- 手机热点通常**禁 ICMP**：`ping` 不通**不代表**连不上，要用 **TCP** 判断：

```powershell
Test-NetConnection 10.68.1.43 -Port 22          # TcpTestSucceeded = True 即通
Test-NetConnection 121.40.149.155 -Port 2222
```

> ⚠️ 比赛纪律：**遥控阶段用手机热点/局域网属于违规**（罚 200s）。比赛必须走小车自带 4G/5G 模块（`car-dial`）。开发期热点可用。

## 3. 助手脚本（免交互，AI 首选）

本机 Windows 已装 paramiko，脚本在 `scripts/`：

```powershell
# 执行命令（默认走隧道）
python scripts/ssh_car.py uname -a
python scripts/ssh_car.py "uname -a; uptime"
python scripts/ssh_car.py --direct hostname -I        # 热点直连兜底
python scripts/ssh_car.py --timeout 60 "ps aux | head"

# 命令参数以 - 开头时，前面加 -- 分隔
python scripts/ssh_car.py hostname -- -I

# 传文件
python scripts/ssh_put.py 本地文件 /root/远端路径       # 默认走隧道
python scripts/ssh_put.py --direct 本地文件 /root/...   # 热点直连
python scripts/ssh_put.py --server 本地文件 /opt/...    # 传给公网服务器
python scripts/ssh_get.py --server /opt/远端 本地路径    # 从服务器拉回

# 直接操作公网服务器
python scripts/ssh_server.py "systemctl status frps"
```

脚本内部是 `paramiko.SSHClient` + `AutoAddPolicy`，用户名/密码硬编码在文件顶部常量，输出 stdout/stderr + `[exit code: N]`。

**降级路径**（paramiko 坏掉时）：`plink -ssh -pw orangepi -batch root@121.40.149.155 -P 2222 "uname -a"`（本机未装 plink）。Windows 自带 `ssh.exe` 无法脚本化输密码，只适合人工用。

> ⚠️ **不要乱动小车上的服务/进程**：实测负载 3~4，可能有别的任务/人在用。只做只读检查，改配置前先记录原值。车端/systemd 改动须经队长确认。

## 4. frp 部署（服务端，可复现）

### 4.1 ⚠️ 安装顺序坑（实测踩过）

解压官方 release 包会**覆盖同名的 `frps.ini`**（包内默认配置只有 `bind_port`、没有 token）。
**正确顺序**：先解压 → **再**写入自定义 `frps.ini`。部署后必须 `grep token /opt/frp/frps.ini` 有输出，否则小车端报 `token in login doesn't match`。

### 4.2 安装

```bash
cd /opt
wget https://github.com/fatedier/frp/releases/download/v0.39.0/frp_0.39.0_linux_amd64.tar.gz
tar xzf frp_0.39.0_linux_amd64.tar.gz && mv frp_0.39.0_linux_amd64 frp
/opt/frp/frps --version        # 应输出 0.39.0（下载慢可用镜像/加速前缀，但版本必须一致）
```

### 4.3 服务端配置 `/opt/frp/frps.ini`

```ini
[common]
bind_port = 7000
token = 375b12b2e5614357ce8225bcce93df4e
# dashboard_port = 7500   # 可选
# dashboard_user = admin
# dashboard_pwd  = 换成强密码
```

### 4.4 systemd

```ini
# /etc/systemd/system/frps.service
[Unit]
Description=FRP Server Service
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/opt/frp/frps -c /opt/frp/frps.ini
WorkingDirectory=/opt/frp
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now frps
systemctl status frps --no-pager | head -10
```

### 4.5 防火墙（两层都要放行）

1. **服务器系统防火墙**：`ufw allow 7000/tcp && ufw allow 2222/tcp`（或 firewalld 对应命令）
2. **★阿里云安全组**（最容易漏）：入方向放行 TCP `7000`、`2222`、`8080`

### 4.6 验证三步

1. 服务器 `ss -lntp | grep frps` → 见 `:7000`；小车连上后多出 `:2222`
2. 小车 `journalctl -u frpc-ssh -n 5` → 出现 `start proxy success`
3. 任意机器 `ssh -p 2222 root@121.40.149.155` 能登录

### 4.7 部署记录（2026-09-02 实测）

| 项 | 结果 |
|---|---|
| 服务器 frps 0.39.0（Ubuntu 26.04 x86_64） | ✅ systemd active，监听 `*:7000` |
| 小车 frpc-ssh（frp 0.39.0 ARM64，复用官方二进制） | ✅ enabled，日志 `login to server success` + `[ssh] start proxy success` |
| 公网 `ssh -p 2222` | ✅ 落到小车（orangepi5 / aarch64） |

## 6. 把服务器当 RKNN 转换机

> 目标：在现有 frp 服务器（**2 核 / 1.6G 内存 / 4G swap / Ubuntu 26.04 x86_64**）上把 ONNX 转成 RKNN。
> 结论：**可以用，但内存紧张**。转 YOLO11n 量级的小模型靠 swap 能扛住；OOM 时加 swap 或临时停 frps。

### 6.1 装兼容的 Python（RKNN-Toolkit2 需要 3.10/3.11，服务器默认 3.14 太新）

```bash
# 方式一：Miniconda（推荐）
cd /opt
wget https://repo.anaconda.com/miniconda/Miniconda3-py311_24.1.2-0-Linux-x86_64.sh
bash Miniconda3-py311_24.1.2-0-Linux-x86_64.sh -b -p /opt/conda
export PATH=/opt/conda/bin:$PATH
conda create -n rknn python=3.11 -y && conda activate rknn

# 方式二：deadsnakes PPA
apt install -y software-properties-common
add-apt-repository -y ppa:deadsnakes/ppa
apt install -y python3.10 python3.10-venv python3.10-dev
python3.10 -m venv /opt/rknn-venv && source /opt/rknn-venv/bin/activate
```

### 6.2 系统依赖与 RKNN-Toolkit2

```bash
apt update && apt install -y python3-dev build-essential cmake \
    libxslt1-dev libglib2.0-0 libgl1 libgomp1

pip install --upgrade pip
pip install rknn-toolkit2          # PyPI 没有或版本不符时，用 Rockchip GitHub 的 wheel
python -c "from rknn.api import RKNN; print('rknn-toolkit2 ok')"
```

### 6.3 传文件与转换

```bash
scp best.onnx root@121.40.149.155:/opt/rknn/          # 或用 scripts/ssh_put.py --server
cd /opt/rknn && source /opt/conda/bin/activate rknn
python convert_rknn.py --onnx best.onnx --output best_int8.rknn \
  --platform rk3588 --quantize --dataset dataset.txt
```

### 6.4 把 RKNN 传到小车

```bash
# 小车走 frp 隧道，先到服务器再到小车；或直接在服务器上通过隧道口转发
scp -P 2222 best_int8.rknn root@121.40.149.155:/root/dev/models/
```

### 6.5 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `Killed`（OOM） | 加 swap：`fallocate -l 8G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`；或 `systemctl stop frps` 腾内存，转完再起 |
| `ModuleNotFoundError: No module named 'rknn'` | 不在 Python 3.10/3.11 虚拟环境里 |
| 小车加载 RKNN 失败 | ① 平台不是 `rk3588`；② 小车缺 `rknn-toolkit-lite2`；③ 文件不在 `/root/dev/models/`；④ 两端 rknn 版本不匹配 |

## 7. 排障速查（合并版）

| 现象 | 原因 |
|---|---|
| 小车日志 `login to server failed` | 服务器 frps 没起 / 7000 未放行 / token 不一致 |
| 客户端显示成功但 `ssh -p 2222` 连不上 | 2222 未在安全组放行 / 2222 被服务器其它服务占用 |
| `connect: connection refused`（服务器侧） | frps 未启动或没监听 |
| 网页打开但摇杆全失效 / WS 已断开 | 小车 9001（opi-control）崩溃，常见缺 `adafruit_pca9685`：`pip3 install adafruit-circuitpython-pca9685` 后重启服务 |
| 摄像头打不开 | ffmpeg 推流独占设备：先 `systemctl stop ffmpeg-stream.service`（测完恢复） |
| 蜂窝 wwan0 无 IP | `car-dial` 未起 / APN 不对：`systemctl restart car-dial`，APN=cmnet |
| SIM 不识别 | 卡没插到位 / 槽位错：重插、换槽、重启（`CPIN READY` 才算） |
| 官方 car0003 画面是他车 | 官方子域多车共用/路由错：用 8080 入口 + 留证据问官方群 |
| 推流卡顿 | 蜂窝/热点上行差：比赛走 5G 模块，开发走 WiFi；加 `pool_count=5` 消隧道尖峰 |
